# Макеты: выбор файла, имена, папка заявки, превью

[← Оглавление](../README.md)

## Суть

Макеты лежат на Яндекс Диске. Правило решает, какой файл — макет артикула, как собрать папку макетов заявки в фоне, как назвать загруженный файл и как отдать превью. Всё это делает сервер (`apps-script/Code.gs`, раздел «Макеты на Яндекс Диске» и ниже).

Что видит админ на сайте: папка заявки — [layout-bundle.md](../components/layout-bundle.md); артикулы с макетами — [article-card.md](../components/article-card.md), [layout-viewer.md](../components/layout-viewer.md); загрузка — [layout-upload.md](../components/layout-upload.md).

## Правила

### Настройки

- **LAYOUT-01.** Всё про макеты работает, только если задано свойство скрипта `YANDEX_DISK_TOKEN`. Без него: заявка в очередь не ставится, колонки F–H «Заявок» не трогаются; `rebuildLayouts`, `articleLayouts`, `layoutPreviews`, `uploadLayout` отвечают `LAYOUTS_NOT_CONFIGURED` «Сборка макетов не настроена: нет токена Яндекс Диска».
- **LAYOUT-02.** Папка макетов — `LAYOUTS_ROOT`, по умолчанию `disk:/ФБ-ПРИНТ/ГлобалФуд_СтудияВкуса/Актуальные_макеты`. Папка для папок заявок — `LAYOUTS_ORDERS_ROOT`, по умолчанию `disk:/ФБ-ПРИНТ/Макеты_по_заявкам`. Путь приводится к виду `disk:/…` без «/» в конце.
- **LAYOUT-03.** Папка заявок не может совпадать с папкой макетов или лежать внутри неё (сравнение без учёта регистра и «ё»/«е»): иначе копии нашлись бы как макеты. Тогда ошибка настройки: «папка заявок {путь} совпадает с папкой макетов {путь} или лежит внутри неё — измените LAYOUTS_ORDERS_ROOT» (см. `LAYOUT-24`).

### Какой файл — макет артикула

- **LAYOUT-04.** Имена сравниваются по ключу: пробелы по краям обрезаются, буквы строчные, «ё» = «е».
- **LAYOUT-05.** Список файлов берётся из папки макетов вместе с вложенными папками: не глубже 4 уровней, не больше 200 папок (остальные пропускаются с записью в журнал), страницами по 1000. Папка заявок при обходе пропускается. Нет самой папки макетов — ошибка «Нет папки макетов {путь}».
- **LAYOUT-06.** Правило имени: имя без расширения делится по «_»; первая часть — буквы (префикс), вторая — артикул. Меньше двух частей или пустая часть — файл правилу не подходит. Префикс (`ГФ`, `СВ`) не сравнивается: раньше все макеты называли `ГФ`.
- **LAYOUT-07.** Если в колонке H «Макет» листа артикулов есть имя, макет — файл с таким именем (по ключу `LAYOUT-04`), в любой вложенной папке; из нескольких — первый по пути. Нет такого файла — проблема `notFound`. Правило имени при этом не применяется.
- **LAYOUT-08.** Если H пуста, макет — файл, у которого вторая часть имени равна артикулу (по ключу). Ровно один — он. Ни одного — проблема `missing`. Два и больше — проблема `conflict`, скрипт не угадывает; имена всех подходящих файлов — в `candidates`.
- **LAYOUT-09.** Значение H читается по паре «компания (лист) + артикул». Если артикул на листе встречается дважды, берётся первое непустое значение; два разных значения — предупреждение в журнал, берётся первое.
- **LAYOUT-10.** Одно правило работает везде: сборка папки заявки, вкладка «Артикулы» (`articleLayouts`), поиск старых файлов при загрузке макета, заполнение колонки H.

### План папки заявки

- **LAYOUT-11.** Позиции заявки берутся с листа «Позиции заявок». Повтор пары «компания + артикул» считается один раз; позиция без артикула пропускается. Если два артикула ведут к одному файлу (общий артикул обеих компаний, одно имя в H у двух артикулов), файл копируется один раз. `total` — число разных пар.
- **LAYOUT-12.** Подпись артикула в проблемах и сообщениях — буквы компании и артикул: «ГФ 10165», «СВ 15053». Буквы — по листу компании («Глобал Фуд» — `ГФ`, «Студия Вкуса» — `СВ`). Позиция неизвестной компании — проблема `missing` с подписью «{название компании} {артикул}».
- **LAYOUT-13.** Тексты проблем (колонка H «Заявок», Telegram, сайт):

  | Вид | Текст |
  | --- | --- |
  | `missing` — файла нет | «ГФ 10003» |
  | `conflict` — несколько файлов | «ГФ 10165 — несколько файлов» |
  | `notFound` — файла из колонки «Макет» нет | «СВ 15053 — нет файла «СВ_15053_x.jpg»» |
  | `failed` — копирование не удалось | «ГФ 10338 — файл пропал с Диска», «ГФ 10338 — Яндекс Диск не скопировал файл (500)», «ГФ 10338 — Яндекс Диск не скопировал файл» |

  В колонке H проблемы записаны через «, », не длиннее 45 000 знаков.

### Сборка папки заявки

- **LAYOUT-14.** Имя папки — номер и время отправки по Москве в формате `ЧЧ.ММ.СС`: `FB-0042 от 09.11.2026 18.10.05`. Знаки `/ \ : * ? " < > |` заменяются на «-». Если в колонке B не дата — только номер. Папка лежит прямо в `LAYOUTS_ORDERS_ROOT`, одна на заявку, без подпапок по компаниям. Время в имени различает заявки с повторно выданным номером.
- **LAYOUT-15.** Нет позиций на листе — статус «Ошибка» с причиной «нет позиций на листе «Позиции заявок»». Ни одного файла для копирования — статус «Макетов нет», папка не создаётся.
- **LAYOUT-16.** Папка создаётся; если её нет вместе с родителем — сначала родитель. Уже существующая папка — не ошибка.
- **LAYOUT-17.** Файлы копируются с исходными именами, пачками по 20, с перезаписью. Обычная сборка пропускает файлы, которые уже лежат в папке (продолжение прерванной сборки). Сборка «заново» (`LAYOUT-33`) копирует всё снова.
- **LAYOUT-18.** Ответ Диска на копирование: 201 — готово; 202 — Диск копирует сам, операция опрашивается раз в секунду до `success` или `failed`; 404 — «файл пропал с Диска»; 423, 429, 5xx — один повтор через 2 секунды, потом «Яндекс Диск не скопировал файл ({код})»; другой код — то же; операция `failed` — «Яндекс Диск не скопировал файл». 401 и 403 прерывают всю сборку (`LAYOUT-27`).
- **LAYOUT-19.** После копирования папка публикуется, ссылка (`public_url`) пишется в колонку F. Открыть папку может любой, у кого есть ссылка. Диск не вернул ссылку — временная ошибка (`LAYOUT-28`).
- **LAYOUT-20.** Итог: проблем нет — «Готово»; есть проблемы плана или копирования — «Не все макеты».

### Очередь

- **LAYOUT-21.** После того как заявка ушла менеджеру, её строка на «Заявках» получает F — пусто, G — «В очереди», H — пусто, и ставится разовый запуск сборки через 10 секунд. Сбой постановки в очередь только пишется в журнал: клиент получает номер заявки как обычно.
- **LAYOUT-22.** Разовый запуск один на всех: если он уже стоит, второй не ставится. Запуск удаляет свой разовый триггер, ежечасный не трогает. Ежечасный запуск ставит `setupLayouts` — страховка, если разовый не сработал.
- **LAYOUT-23.** Запуск живёт до 270 секунд. Он берёт блокировку документа на 1 секунду; занята — ничего не делает (`busy`). Эта блокировка отдельна от блокировки скрипта: отправка, удаление и статус заявок не ждут сборку. Заявки берутся сверху вниз со статусом «В очереди»; список файлов и колонка H читаются один раз за запуск.
- **LAYOUT-24.** Ошибка настройки папок (`LAYOUT-03`): все ждущие заявки получают «Ошибка», F и H очищаются, в Telegram — одно сообщение «⚠ Макеты не собираются: {ошибка}.\nЗаявки: {номера}.».
- **LAYOUT-25.** «Собирается» в начале запуска значит, что прошлый запуск оборвался. Счётчик попыток растёт на 1. На третьей попытке — «Ошибка» с причиной «сборка несколько раз прервалась»; иначе заявка снова «В очереди».
- **LAYOUT-26.** Перед сборкой заявка получает «Собирается». Строка ищется по номеру и дате отправки: после удалений строки сдвигаются, а номер мог выдаться снова. Итог пишется в F–H, только если строка нашлась и в G всё ещё «Собирается». Иначе (заявку удалили или снова поставили в очередь) итог не пишется. После записи счётчик попыток и пометка «заново» забываются, в Telegram уходит сообщение `LAYOUT-36`. Текст, начинающийся с `=`, `+`, `-`, `@`, пишется с апострофом, чтобы таблица не сочла его формулой.
- **LAYOUT-27.** Диск не принял токен (401, 403 или токена нет): заявка возвращается в «В очереди», запуск останавливается. Скрипт ставит предупреждение `LAYOUT_ALERT` с текстом «Яндекс Диск не принимает токен — макеты не собираются. Замените YANDEX_DISK_TOKEN в свойствах скрипта.» и шлёт в Telegram сообщение о токене не чаще раза в 12 часов. Любой успешный ответ Диска снимает предупреждение.
- **LAYOUT-28.** Временная ошибка (сеть, 423, 429, 5xx при создании папки, списке, публикации): счётчик попыток растёт. Меньше трёх — заявка снова «В очереди», следующий запуск через 5 минут. Третья — «Ошибка» с текстом ошибки как причиной. Очередь идёт дальше.
- **LAYOUT-29.** Любая другая ошибка — сразу «Ошибка» с текстом ошибки. Очередь идёт дальше.
- **LAYOUT-30.** За 30 секунд до конца запуска новая заявка не берётся: ставится продолжение через 60 секунд. Если время кончилось посреди копирования, заявка возвращается в «В очереди», пометка «заново» снимается (скопированное уже свежее), продолжение через 60 секунд пропустит готовые файлы.
- **LAYOUT-31.** При «Ошибке» F и H очищаются, в Telegram — сообщение об ошибке (`LAYOUT-36`). При удалении заявки счётчик попыток и пометка «заново» забываются; папка на Диске остаётся.
- **LAYOUT-32.** Статусы колонки G и ключи для сайта:

  | Ключ | Слово в G | Значит |
  | --- | --- | --- |
  | `queued` | «В очереди» | ждёт запуска |
  | `building` | «Собирается» | идёт сборка |
  | `done` | «Готово» | все макеты скопированы |
  | `partial` | «Не все макеты» | папка есть, есть проблемы |
  | `empty` | «Макетов нет» | ни одного файла, папки нет |
  | `failed` | «Ошибка» | не собрано |
  | `''` | пусто или другое слово | старая заявка или сборка выключена |

### Собрать заново

- **LAYOUT-33.** `rebuildLayouts` берёт самую нижнюю строку с этим номером: G — «В очереди», H — пусто, ссылка в F остаётся. Счётчик попыток обнуляется, ставится пометка «заново», разовый запуск через 10 секунд. Ответ: `{ ok: true, number, layouts: { status: "queued", url, problems: [] } }`.
- **LAYOUT-34.** Ошибки: строки нет — `ORDER_NOT_FOUND` «Заявка {номер} не найдена — возможно, её уже удалили»; прочее — `LAYOUTS_QUEUE_FAILED` «Не удалось поставить сборку макетов в очередь: …». Проверки роли, номера и токена — [layout-bundle.md](../components/layout-bundle.md), `LBUNDLE-16`.
- **LAYOUT-35.** Пересборка во время сборки той же заявки не теряется: итог текущей сборки не перезапишет «В очереди» (`LAYOUT-26`), и заявка соберётся заново с копированием всех файлов.

### Сообщения

- **LAYOUT-36.** После сборки сервер шлёт в Telegram одно сообщение об итоге. Сбой отправки пишется только в журнал и на сборку не влияет. Тексты сообщений и сокращение длинных списков — в [telegram.md](telegram.md): итог сборки — TG-21…TG-24, предупреждение о токене — TG-28, TG-29.
- **LAYOUT-37.** Итог запуска (журнал и окно меню): «Собрано заявок: {N}.», при остатке «В очереди: {N}.» и причина остановки: «Сборка уже идёт в другом запуске — попробуйте через несколько минут.», текст предупреждения о токене, «Время запуска кончилось — остальное соберётся само в течение минуты.», «Сборка выключена: неверные папки в свойствах скрипта, подробности — в журнале и Telegram.».

### Таблица: меню и настройка

- **LAYOUT-38.** При открытии таблицы появляется меню «FB Print» с пунктами:
  - «Собрать макеты для выделенной заявки» — пересобирает заявку из выделенной строки листа «Заявки» (`LAYOUT-33`) и сразу запускает очередь; итог — окном `LAYOUT-37`. Не тот лист — «Выделите строку заявки на листе «Заявки».»; в строке нет номера `FB-…` — «В выделенной строке нет номера заявки.»; нет токена — «Сборка макетов не настроена: нет токена Яндекс Диска».
  - «Собрать очередь макетов сейчас» — запускает очередь, не дожидаясь триггера; итог — окном.
- **LAYOUT-39.** Колонки F–H «Заявок» — «Папка макетов», «Макеты», «Проблемы с макетами», в формате заголовка D1, ширина 280, 130, 320. Их пишут `setupOrdersSheet` и `setupLayouts`.
- **LAYOUT-40.** Админ получает в ответе `orders` у каждой заявки `layouts`: `status` — ключ по слову из G (`LAYOUT-32`), `url` — F, `problems` — H, разрезанная по «, », без пустых. И общий `layoutsAlert` — текст `LAYOUT_ALERT` или пусто. Клиент этих полей не получает.
- **LAYOUT-41.** `setupLayoutColumn` (запуск в редакторе) пишет заголовок «Макет» в H2 обоих листов артикулов в формате G2, ширина 240, если H2 пуста. Если в H2 другой текст — лист не меняется, в журнале ««{лист}»: в H2 уже стоит «{текст}» — лист не изменён. Освободите колонку H и запустите снова.».
- **LAYOUT-42.** `fillLayoutColumn` заполняет по правилу имени только пустые ячейки H. Ручные значения не трогает никогда. Повтор артикула получает то же имя. Без токена или с ошибкой папок ничего не заполняет. В журнал: сколько файлов и сколько ячеек заполнено; артикулы без файла; артикулы с несколькими файлами и их имена (ячейки остаются пустыми); значения H, которых нет на Диске; файлы, не подошедшие ни одному артикулу. Повторный запуск ничего не меняет.
- **LAYOUT-43.** `setupLayouts` (один раз после добавления токена): предупреждает в журнале, если `ADMIN_PASSWORD` не задан или совпадает с `ACCESS_PASSWORD`; пишет заголовки F–H; без токена или с ошибкой папок останавливается; ставит ежечасный запуск, если его нет; проверяет токен; пишет число файлов и 20 примеров имён; создаёт папку заявок.
- **LAYOUT-44.** Служебные свойства `LAYOUT_TRIGGER_ID`, `LAYOUT_ATTEMPTS`, `LAYOUT_FRESH`, `LAYOUT_ALERT`, `LAYOUT_ALERT_SENT_AT` ведёт сам скрипт.

### Вкладка «Артикулы» и превью

- **LAYOUT-45.** `articleLayouts` (только админ) отдаёт каждую строку листов артикулов с артикулом: найденный макет по `LAYOUT-07`/`LAYOUT-08`, его путь, `problem` и `candidates`, значение H как есть (`layoutCell`) и список всех имён файлов. Ссылка на файл ведёт в веб-интерфейс Диска (папка файла с открытым просмотром) и работает только у того, кто вошёл в этот аккаунт Яндекса. Файлы не публикуются. Сбой — `ARTICLES_READ_FAILED` «Не удалось прочитать артикулы и макеты: …»; при отказе токена причина — текст `LAYOUT-27`.
- **LAYOUT-46.** `layoutPreviews` (только админ, нужен токен) принимает до 12 путей за запрос, лишние отбрасываются; путь обрезается до 500 знаков. Размер `M` (около 300 px, по умолчанию) или `XL` (около 800 px); другое значение — `M`. Ответ называет размер в `size`.
- **LAYOUT-47.** Превью отдаётся картинкой `data:image/…;base64,…`. Путь вне папки макетов (или с `..`), файл без превью, ответ не 200 или не картинка — пустая строка.
- **LAYOUT-48.** Готовое превью лежит в кэше скрипта 6 часов по ключу «размер + путь». Не кэшируются картинки больше 100 000 знаков и пути, у которых ключ длиннее 250 знаков.
- **LAYOUT-49.** Диск ответил 401 на запрос превью — `LAYOUT_PREVIEW_FAILED` «Не удалось загрузить превью макетов: {текст LAYOUT-27}». Сеть недоступна — тот же код с текстом ошибки.

### Загрузка макета (сервер)

Интерфейс — [layout-upload.md](../components/layout-upload.md).

- **LAYOUT-50.** Проверки `uploadLayout`: только админ; нужен токен; компания известна; тип `image/jpeg`, `image/png` или `application/pdf`, иначе «Макет должен быть JPG, PNG или PDF»; файл не читается — «Файл не прочитался. Выберите его ещё раз»; пустой — «Файл пустой»; больше 20 МБ — «Файл больше 20 МБ» (все — `LAYOUT_UPLOAD_INVALID`). В строке `row` должен быть этот артикул, иначе `ARTICLE_CHANGED` ([article-dialog.md](../components/article-dialog.md)).
- **LAYOUT-51.** Размер для имени берётся из колонки D строки: пробелы вокруг «x», «х», «X», «Х», «×», «*» перед цифрами убираются, знак становится латинской «x»; все пробелы и знаки `\ / : * ? " < > | _` удаляются. «80 х 120» → `80x120`, «D80» → `D80`.
- **LAYOUT-52.** Имя: `{ГФ|СВ}_{артикул}_{размер}.{jpg|png|pdf}`; без размера — `{ГФ|СВ}_{артикул}.{расширение}`. Если такое имя (по ключу `LAYOUT-04`) уже есть среди всех файлов папки макетов — `…_{артикул}_2_{размер}…`, затем `_3_` и так далее.
- **LAYOUT-53.** Файл кладётся прямо в `LAYOUTS_ROOT`, без перезаписи существующего.
- **LAYOUT-54.** Имя пишется в колонку H всех строк с этим артикулом на обоих листах (артикул сравнивается по ключу `LAYOUT-04`).
- **LAYOUT-55.** Прежние файлы артикула — те, что были в H этих строк, и те, что подходят по правилу имени, — уходят в корзину Диска (не навсегда). Не трогаются новый файл и файлы вне папки макетов. Если файл не ушёл в корзину — только запись в журнал. Ответ: `{ ok: true, name, path, trashed: [имена] }`.
- **LAYOUT-56.** Сбой Диска — `LAYOUT_UPLOAD_FAILED` «Не удалось загрузить макет: …»; при отказе токена причина — текст `LAYOUT-27`.

### Безопасность

- **LAYOUT-57.** Токен уходит только на `https://cloud-api.yandex.net/`. Адрес операции копирования на другом хосте — ошибка «Яндекс Диск вернул неожиданный адрес операции». Превью скачиваются и файлы загружаются только по адресам `yandex.ru` и `yandex.net`. Токен не пишется в журнал и в ответы.

## При переносе

> [!note] При переносе
> Макет — запись `layouts` (организация + код артикула + файл), один текущий на код. Файлы — таблица `files`, Яндекс Диск остаётся за интерфейсом `files` (позже можно S3). Колонка H и правило имени переносятся один раз при импорте. Папку заявки собирает фоновая задача Go-воркера, состояние — `order_layout_bundles` с попытками и последней ошибкой вместо колонок F–H и свойств скрипта. Превью — `GET /admin/layouts/{id}/preview?size=M` картинкой, загрузка — `multipart/form-data`. В таблицу F–H пишутся из базы, назад не читаются. Номер заявки больше не повторяется, поэтому время в имени папки нужно только для старых заявок.

> [!warning] Расхождение
> `API_CONTRACT.md` в таблице ошибок относит `LAYOUTS_NOT_CONFIGURED` только к `rebuildLayouts`, `articleLayouts`, `layoutPreviews`. Код отдаёт его ещё и `uploadLayout`. README в разделе «Колонки «Заявок»» не называет проблему копирования «… — файл пропал с Диска» / «… — Яндекс Диск не скопировал файл», а `API_CONTRACT.md` называет.

> [!warning] Расхождение
> Пункт меню «Собрать макеты для выделенной заявки» берёт номер из выделенной строки, но пересобирает самую нижнюю строку с этим номером. Если номер выдан повторно, соберётся не та заявка.

> [!warning] Расхождение
> Превью при ответе Диска 403 не даёт ошибку токена, а возвращает пустые строки: проверяется только 401.
