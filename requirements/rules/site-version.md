# Версия сайта и обновление

[← Оглавление](../README.md)

## Суть

Браузер должен брать новый файл, как только он изменился. А вкладка, открытая давно, должна узнать, что сайт обновился, и не отправлять заявку старым кодом. Для этого у каждого файла есть метка по содержимому, а у сайта — общая версия.

## Правила

### Метки файлов

- **VER-01.** Метка файла — первые 10 шестнадцатеричных символов SHA-256 его содержимого. Перед хэшированием переводы строк `CRLF` заменяются на `LF`: метка не зависит от того, как Git выгрузил файл.
- **VER-02.** Метки получают файлы в таком порядке: `tokens.css`, `style.css`, `config.js`, затем все модули `js/*.js` по алфавиту. От порядка зависит версия сайта (VER-04).
- **VER-03.** Метка добавляется к адресу файла: `style.css?v=<метка>`. Стили, `config.js` и `js/main.js` — прямо в ссылках `index.html`. Остальные модули из `js/` — через карту импортов (`importmap`): `./js/order.js` → `./js/order.js?v=<метка>`.
- **VER-04.** Версия сайта — первые 10 символов SHA-256 от строк `<файл>:<метка>`, соединённых переводом строки. Она записана в `<meta name="app-version" content="…">`.
- **VER-05.** Изменился один файл — меняются его метка и версия сайта. Метки остальных файлов те же, их копии остаются в кэше браузера.

### Инструмент `tools/stamp-version.mjs`

- **VER-06.** `node tools/stamp-version.mjs` переписывает в `index.html` блок между `<!-- Версии файлов: node tools/stamp-version.mjs. Не правьте руками. -->` и `<!-- /версии файлов -->`: мета-тег версии, две ссылки на стили и карту импортов. Затем ставит метки у `config.js` и `js/main.js`.
- **VER-07.** Первый запуск без блока: блок встаёт на место двух ссылок `tokens.css` и `style.css`. Если их нет — ошибка «В index.html не найдены ссылки на tokens.css и style.css».
- **VER-08.** Повторный запуск без изменений файлов ничего не меняет. Сообщения: «Версии не изменились» или «index.html обновлён, версия сайта <версия>».
- **VER-09.** `--check` только проверяет. Метки устарели — «Версии в index.html устарели: запустите node tools/stamp-version.mjs» и код выхода 1. Иначе — «Версии в index.html актуальны».
- **VER-10.** Тест `tests/version.test.js` падает, если метки в `index.html` устарели или какой-то модуль из `js/` не попал в карту импортов. Инструмент запускают перед каждым коммитом, который меняет стили, `config.js` или `js/`.

### Проверка версии в открытой вкладке

- **VER-11.** Свежая версия — из `index.html` рядом с текущей страницей, запрошенного с параметром `?check=<время в мс>` и `cache: 'no-store'`. Ожидание — 5 с.
- **VER-12.** Вкладка устарела, только если свою версию удалось прочитать, свежую тоже и они разные. Нет связи, ответ не 2xx, в ответе нет мета-тега, у страницы нет версии (локальный запуск) — вкладка считается свежей. Проверка не должна мешать работе.
- **VER-13.** Проверка при возвращении на вкладку: когда вкладка снова видна, прошло не меньше 10 минут с прошлой проверки, а обновление ещё не предлагали. Отсчёт первой проверки — с загрузки страницы. Время проверки запоминается до запроса, даже если он не удастся.
- **VER-14.** Вкладка устарела — уведомление «Сайт обновился. Обновите страницу — заявка сохранится.» с кнопкой «Обновить». Кнопка перезагружает страницу. Уведомление не исчезает само ([ui-toast.md](../components/ui-toast.md)). За жизнь страницы оно предлагается один раз.
- **VER-15.** Перед отправкой заявки версия проверяется всегда. Вкладка устарела — заявка не отправляется, страница перезагружается. Черновик сохраняется в браузере ([order-draft.md](order-draft.md)). Текст после перезагрузки — в [order-submission.md](order-submission.md).
- **VER-16.** Перезагрузка «для обновления» кладёт текст сообщения в `sessionStorage` под ключом `fbprint-updated`. После загрузки страница показывает это сообщение уведомлением, которое не исчезает само, и удаляет ключ. Хранилище недоступно — страница перезагружается без сообщения.

## Примеры

| Своя версия | Свежая версия | Результат |
| --- | --- | --- |
| `aaaaaaaaaa` | `bbbbbbbbbb` | устарела |
| `aaaaaaaaaa` | `aaaaaaaaaa` | свежая |
| `aaaaaaaaaa` | сеть недоступна | свежая |
| `aaaaaaaaaa` | ответ без мета-тега | свежая |
| нет мета-тега | `bbbbbbbbbb` | свежая |

## При переносе

> [!note] При переносе
> `version.js` и `tools/stamp-version.mjs` не нужны: сборка Angular сама добавляет хэш к именам файлов. Проверку новой версии делают через `ngsw` или опрос `/api/v1/version` ([план](../../docs/platform-plan.md), «Перенос модулей»). Поведение VER-12–VER-16 стоит сохранить: заявку не отправляет старый код, черновик не теряется.
