# Черновик заявки: хранение, вкладки, пересчёт

[← Оглавление](../README.md)

## Суть

Черновик — позиции, собранные на вкладке «Расчёт» и ещё не отправленные. Он живёт в браузере: переживает перезагрузку, выход и закрытие вкладки, общий для всех вкладок сайта. Цены в черновике пересчитываются по каждому свежему каталогу.

## Правила

### Хранение

- **DRAFT-01.** Черновик хранится в `localStorage` под ключом `fbprint-order`: JSON-массив позиций в порядке добавления.
- **DRAFT-02.** Позиция хранится так:

| Поле | Что это |
| --- | --- |
| `id` | случайный UUID позиции |
| `key` | `{id компании}/{артикул}`, например `global_food/10165` |
| `company` | название компании на момент добавления |
| `sku`, `name` | артикул и наименование |
| `size` | размер из категории (нужен для Excel) |
| `quantity` | тираж, целое число |
| `urgency` | `standard`, `urgent` или `emergency` |
| `unitPrice` | цена за штуку |
| `total` | сумма позиции, до копеек |
| `status` | `good`, `reduced` (сниженный тираж) или `multiple` (не кратен) |
| `problem` | только у позиции, которую нельзя заказать: `{label, hint}` (DRAFT-14) |

- **DRAFT-03.** Черновик записывается после каждого изменения: добавление, удаление, «Вернуть», изменение тиража, пересчёт, очистка, синхронизация, успешная отправка.
- **DRAFT-04.** Хранилище недоступно (приватный режим, запрет) — черновик живёт в памяти вкладки до её закрытия. Ошибки на экране нет.
- **DRAFT-05.** При открытии страницы черновик читается из хранилища до загрузки каталога. Позиции без `id`, без `key` или с тиражом не больше 0 отбрасываются. Испорченный JSON или не массив — черновик пуст. Остальные поля не проверяются.
- **DRAFT-06.** До загрузки каталога позиции показываются с сохранёнными ценами и пометками. После загрузки — пересчёт (DRAFT-13).

### Состав

- **DRAFT-07.** Один артикул компании — одна позиция. Позиции не сливаются и не дублируются: тот же артикул той же компании второй раз не добавить ни из калькулятора, ни из Excel ([price-ticket.md](../components/price-ticket.md), [article-search.md](../components/article-search.md), [excel-import.md](excel-import.md)). Тираж меняется в [таблице](../components/order-table.md). Тот же артикул другой компании — отдельная позиция.
- **DRAFT-08.** Новая позиция ставится в конец. Порядок добавления — порядок по умолчанию в таблице, порядок в Excel и в отправленной заявке.
- **DRAFT-09.** Позиция создаётся из артикула и расчёта цены ([pricing.md](pricing.md)): название компании, наименование, размер — из каталога; срок, цена и замечание — из расчёта; сумма — тираж × цена, до копеек ([formatting.md](formatting.md)).
- **DRAFT-10.** Итог черновика — сумма сумм позиций, до копеек.
- **DRAFT-11.** Удаление позиции и очистка заявки обратимы: уведомление с кнопкой «Вернуть» ([order-table.md](../components/order-table.md), [order-panel.md](../components/order-panel.md)).
- **DRAFT-12.** «Вернуть» ставит каждую удалённую позицию на её прежний номер в списке (если список стал короче — в конец). Позиция не возвращается, если позиция с тем же `key` уже есть в черновике.

### Пересчёт

- **DRAFT-13.** Пересчёт идёт после каждой загрузки каталога: при входе, по кнопке обновления, после правки артикулов и категорий администратором, в демо-режиме — по демо-каталогу. Пустой каталог (нет компаний) или пустой черновик — пересчёта нет.
- **DRAFT-14.** Для каждой позиции:
  - артикула или его категории нет в каталоге — пометка «Нет в каталоге», подсказка «Удалите позицию или спросите менеджера FB-print.»;
  - тираж теперь ниже допустимого — пометка «Тираж мал», подсказка «Минимальный заказ — {N} шт. Измените тираж или удалите позицию.»;
  - иначе пометка снимается, а наименование, размер, срок, цена, сумма и замечание берутся по текущим правилам. Тираж ниже минимального заказа — срок становится стандартным.
- **DRAFT-15.** Пересчёт не меняет тираж и название компании. Позиция с пометкой сохраняет прежние цену и сумму.
- **DRAFT-16.** После пересчёта — уведомление с крестиком:
  - есть позиции с пометкой — «{N} позицию / позиции / позиций в заявке нельзя заказать: причина указана в строке.»;
  - иначе, если у каких-то позиций изменились цена или срок, — «Цены в заявке обновлены: {N} позиция / позиции / позиций.»;
  - иначе уведомления нет.

### Блокировка

- **DRAFT-17.** Пока в черновике есть позиция с пометкой, Excel не скачивается и заявка не отправляется. Уведомление с крестиком: «В заявке есть позиции, которые нельзя заказать. Исправьте или удалите их.» Пометку снимают удаление позиции, изменение тиража ([order-table.md](../components/order-table.md), OTABLE-17) или следующий пересчёт.

### Вкладки

- **DRAFT-18.** Черновик общий для всех вкладок сайта. Изменили его в одной вкладке — другие открытые вкладки сразу перечитывают его из хранилища и перерисовывают панель. Срабатывает и при полной очистке хранилища.
- **DRAFT-19.** Если во вкладке были позиции, а после синхронизации черновик пуст, открытое [окно отправки](../components/submit-dialog.md) закрывается и появляется уведомление «Заявку отправили или очистили в другой вкладке.» Так отправленная заявка не уйдёт второй раз из другой вкладки.
- **DRAFT-20.** Пока из этой вкладки уходит заявка, изменения из других вкладок не принимаются.
- **DRAFT-21.** После синхронизации позиции не пересчитываются: берутся как есть, с пометками другой вкладки. Фильтры, сортировка, размер и номер страницы у каждой вкладки свои.

### Прочее

- **DRAFT-22.** Выход ([access-and-roles.md](access-and-roles.md)) черновик не трогает: он остаётся в браузере и на экране, пересчёт не идёт до следующего входа.
- **DRAFT-23.** Демо-режим использует тот же ключ хранилища. Позиции реального каталога в демо-режиме получат пометку «Нет в каталоге».
- **DRAFT-24.** Сайт не ограничивает число позиций в черновике. Сервер принимает до 300 позиций ([order-submission.md](order-submission.md), OSEND-18).
- **DRAFT-25.** После успешной отправки черновик очищается сразу ([order-submission.md](order-submission.md), OSEND-14).
- **DRAFT-26.** При запуске сайт удаляет из `localStorage` устаревший ключ `fbprint-sent-orders` (раньше там хранились отправленные заявки).

## Примеры

| Вход | Результат |
| --- | --- |
| в черновике 4 000 шт. по 0,90 ₽, в каталоге теперь 1,00 ₽ | цена 1,00 ₽, сумма 4 000 ₽, «Цены в заявке обновлены: 1 позиция.» |
| срочная позиция 2 000 шт., минимум стал 3 000, есть сниженный тираж 1 000–2 999 | срок «Стандартный», цена сниженного тиража, замечание «Сниженный тираж» |
| артикул удалили из таблицы | «Нет в каталоге», отправка и Excel заблокированы |
| тираж 500, минимум 2 000, сниженного нет | «Тираж мал», подсказка «Минимальный заказ — 2 000 шт. …» |
| в хранилище `{"not":"a list"}` | черновик пуст |
| вкладка А отправила заявку, во вкладке Б открыто окно отправки | во вкладке Б окно закрывается, «Заявку отправили или очистили в другой вкладке.» |

## При переносе

> [!note] При переносе
> По [плану](../../docs/platform-plan.md) черновик по-прежнему хранится в `localStorage` и синхронизируется между вкладками. Окончательную цену считает сервер при отправке (`409 PRICES_CHANGED`), поэтому пересчёт на клиенте остаётся подсказкой, а не правдой. Черновики на сервере — на будущее.

## Вопросы

> [!warning] Расхождение
> Если черновик изменили в другой вкладке, пока в этой открыто подтверждение удаления, «Удалить» ничего не удаляет (позиции из старого списка уже нет), но уведомление «Артикул … удалён из заявки.» появляется. «Вернуть» после этого может вставить устаревшую копию позиции.

> [!question] Вопрос
> Пока заявка уходит, вкладка игнорирует изменения из других вкладок (DRAFT-20). Если отправка не удалась, следующее действие в этой вкладке запишет её старый черновик поверх изменений другой вкладки. Нужно ли перечитать черновик после ошибки?

> [!question] Вопрос
> Название компании в позиции не обновляется при пересчёте. Если компанию переименуют, фильтр по компании и Excel покажут старое название. Так и нужно?
