# Запросы к API, тайм-ауты, ошибки, демо-режим

[← Оглавление](../README.md)

## Суть

Сайт общается с одним адресом Apps Script. Все запросы — POST с JSON в теле и паролем. Ошибка приходит в теле ответа, а не HTTP-статусом. Здесь описано, как сайт отправляет запросы, сколько ждёт ответа и что показывает при сбое. Поля запросов и ответов — в `API_CONTRACT.md`.

## Правила

### Запрос

- **API-01.** Адрес API — `window.FBPRINT_CONFIG.apiUrl` из `config.js`, с обрезанными пробелами. Пустая строка или нет поля — демо-режим (API-16).
- **API-02.** Каждый запрос — `POST` на этот адрес. Тело — JSON-строка `{ "action": "…", "password": "…", …поля действия }` ([access-and-roles.md](access-and-roles.md), ACCESS-13).
- **API-03.** Заголовок `Content-Type` сайт не ставит. Браузер отправляет строку как `text/plain;charset=UTF-8`. Так нет CORS-предзапроса, который Apps Script не поддерживает.
- **API-04.** Запросы идут с `redirect: 'follow'`: Apps Script отвечает через перенаправление. Все запросы, кроме отправки заявки, идут с `cache: 'no-store'`.
- **API-05.** Сервер всегда отвечает HTTP 200 и JSON. Ошибка — объект `{ "error": { "code": "…", "message": "…" } }`. Текст `message` написан для пользователя, сайт показывает его как есть.
- **API-06.** Тело не JSON или не объект — `INVALID_REQUEST` «Неверный запрос». Пароль проверяется до разбора действия ([access-and-roles.md](access-and-roles.md), ACCESS-06). Неизвестное `action` с верным паролем — `UNKNOWN_ACTION` «Неизвестное действие».

### Тайм-ауты

- **API-07.** Базовый тайм-аут — `requestTimeoutMs` из `config.js`. Сейчас там 20 000 мс: Apps Script после простоя просыпается несколько секунд. Если поля нет, оно `0` или не число — 10 000 мс.
- **API-08.** Свои тайм-ауты у долгих действий, они не зависят от `config.js`:

| Действие | Тайм-аут |
| --- | --- |
| `catalog`, `orders`, `orderLines`, `setOrderStatus`, `rebuildLayouts` | базовый (API-07) |
| `deleteOrder`, `saveArticle`, `deleteArticle`, `categoryRows`, `saveCategory`, `deleteCategory` | 30 000 мс |
| `articleLayouts`, `layoutPreviews` | 60 000 мс |
| `order` (отправка заявки) | 60 000 мс |
| `uploadLayout` | 180 000 мс |

- **API-09.** По истечении тайм-аута запрос отменяется. Причина ошибки — «Сервер не ответил вовремя» (API-11).
- **API-10.** Новый запрос каталога отменяет предыдущий запрос каталога. То же для списка заявок. Отменённый запрос ничего не показывает: ни ошибки, ни смены экрана загрузки.

### Причина ошибки

- **API-11.** Причина ошибки для человека (`failureReason`), по порядку:
  1. у ошибки есть готовый текст (текст сервера или текст о каталоге) — он;
  2. запрос отменён по тайм-ауту — «Сервер не ответил вовремя»;
  3. сбой сети (`TypeError` у `fetch`) — «Нет связи с сервером»;
  4. всё остальное — «Сервер ответил с ошибкой».
- **API-12.** HTTP-статус не 2xx и ответ не JSON попадают в пункт 4 API-11: «Сервер ответил с ошибкой». Статус проверяют только запросы `catalog` и `order`. Остальные сразу разбирают JSON.
- **API-13.** Действия администратора (`postAction`) считают ошибкой ответ с `error.code` или без `ok: true`. Готовый текст — `error.message`, а если его нет — «Сервер ответил с ошибкой».
- **API-14.** Текст ошибки действия администратора (`adminErrorText`). Для `ADMIN_REQUIRED` и кодов, которые оканчиваются на `_FAILED` или начинаются с `ARTICLE_`, `LAYOUT_UPLOAD_`, `CATEGORY_`, показывается только текст сервера: он уже полный. Для остальных — «<что не получилось>: <причина по API-11>», например «Сборка не запущена: Сборка макетов не настроена: нет токена Яндекс Диска».
- **API-15.** Ошибки запросов пишутся в консоль браузера как предупреждения.

### Демо-режим

- **API-16.** При пустом адресе API сайт не делает ни одного запроса к API. Каталог — встроенный демо-каталог ([catalog-validation.md](catalog-validation.md)). Окна входа нет, роль — клиент, экран загрузки скрыт. Статус в шапке — «Демо-режим», кнопки «Выйти» нет.
- **API-17.** В демо-режиме вкладка «Заявки» пустая, строка обновления — «Демо-режим: заявки появятся после подключения таблицы.».
- **API-18.** В демо-режиме окно отправки заявки показывает «Демо-режим: заявка не уйдёт менеджеру.». «Отправить» закрывает окно и показывает уведомление «Демо-режим: заявка не отправлена менеджеру.». Черновик не очищается.
- **API-19.** Если адрес API задан, демо-данные не показываются никогда, даже когда сервер недоступен.

### Реакция на ошибки по запросам

- **API-20.** Ошибки доступа (`ACCESS_DENIED`, `ACCESS_NOT_CONFIGURED`) обрабатываются по-разному:

| Запрос | Что происходит |
| --- | --- |
| `catalog` | пароль стирается, открывается окно входа ([access-and-roles.md](access-and-roles.md), ACCESS-18) |
| `deleteOrder`, `setOrderStatus`, `rebuildLayouts` | каталог загружается заново; он получит ту же ошибку и откроет окно входа |
| `orders` | строка обновления: «Не удалось загрузить заявки. Обновите страницу.» или «Не удалось обновить заявки — показан последний загруженный список.» ([orders-toolbar.md](../components/orders-toolbar.md)) |
| `order` | ошибка в окне отправки: «Заявка не отправлена: неверный пароль. …» ([order-submission.md](order-submission.md)) |
| `articleLayouts`, `categoryRows` и правки артикулов, категорий, макетов | текст ошибки по API-14, например «Артикулы не загрузились: Неверный пароль» |
| `orderLines` | ошибка внутри раскрытой заявки ([order-lines.md](../components/order-lines.md)) |

- **API-21.** Ошибка загрузки каталога. Окно входа, если было открыто, закрывается. Если каталог уже загружался в этой странице, остаются прежние данные. Если нет — каталог очищается, поиск артикула отключается. Статус в шапке — [data-status.md](../components/data-status.md), предупреждение над калькулятором — [catalog-alert.md](../components/catalog-alert.md).
- **API-22.** Ошибка загрузки каталога показывается в плашке над калькулятором. Заголовки, тексты и совет « Обновите страницу через минуту…» описаны в [catalog-alert.md](../components/catalog-alert.md), CALERT-02…CALERT-05.
- **API-23.** Каталог пришёл, но не прошёл [проверку](catalog-validation.md), или в ответе есть `error` с кодом, кроме ошибок доступа. Это показывается как ошибка в таблице каталога, без совета (CALERT-04, CALERT-05).
- **API-24.** `ADMIN_REQUIRED` на любом действии администратора делает роль клиентской без выхода ([access-and-roles.md](access-and-roles.md), ACCESS-16).

## При переносе

> [!note] При переносе
> API станет REST с префиксом `/api/v1` на том же домене, что и сайт: без CORS и без `text/plain`. Ошибки — настоящие HTTP-статусы (400, 401, 403, 404, 409, 422, 429) и тело `application/problem+json` с тем же `code` и текстом `detail` по-русски. Пароль в теле запросов заменит сессия в cookie. Действия станут путями, таблица соответствия — в [плане](../../docs/platform-plan.md), «API». Холодного старта Apps Script не будет, тайм-ауты можно пересмотреть. Демо-режим без сервера в плане не упомянут.

## Вопросы

> [!warning] Расхождение
> `API_CONTRACT.md`, «Поведение фронтенда при ошибке»: «Ошибка при нажатии «Обновить» после успешной загрузки…». Кнопки «Обновить» для каталога на сайте нет. Повторная загрузка бывает после правки артикулов и категорий и после ошибки доступа в действиях с заявками.

> [!warning] Расхождение
> `API_CONTRACT.md` о коде `ACCESS_DENIED`: «сайт снова показывает окно входа». Так только для `catalog` и действий с заявками (API-20). На вкладках «Артикулы», «Категории», в списке заявок и при отправке заявки показывается текст ошибки, окно входа не открывается.

> [!warning] Расхождение
> `README.md` показывает `requestTimeoutMs: 10000`. В `config.js` — 20 000 мс, 10 000 мс — запасное значение в коде (API-07).

> [!warning] Расхождение
> Ответ `CATALOG_READ_FAILED` («Не удалось прочитать таблицу: …») показывается как «В таблице каталога ошибка (Не удалось прочитать таблицу: …). Сообщите об этом менеджеру FB-print» (API-23). Похоже на ошибку: сбой чтения — не ошибка в таблице.

> [!warning] Расхождение
> Похоже на ошибку. Ошибка доступа очищает каталог, но не сбрасывает время прошлой загрузки. «Выйти» его сбрасывает. Пусть после этого вход срывается из-за сети. Тогда статус и предупреждение говорят «Расчёт идёт по данным, загруженным в ЧЧ:ММ», хотя каталог пуст (API-22).

> [!question] Вопрос
> Списки заявок, позиции и действия администратора не проверяют HTTP-статус (API-12). При переносе на настоящие статусы это нужно будет сделать везде одинаково.
