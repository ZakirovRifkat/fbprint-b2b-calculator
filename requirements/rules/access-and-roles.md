# Пароли, роли, выход

[← Оглавление](../README.md)

## Суть

На сайт входят по одному из двух общих паролей. Клиентский пароль даёт роль `client`, админский — `admin`. Роль решает сервер на каждом запросе. Браузер хранит только пароль.

## Правила

### Пароли и роли на сервере

- **ACCESS-01.** Пароли задаются в свойствах скрипта: `ACCESS_PASSWORD` — клиентский, `ADMIN_PASSWORD` — администратора.
- **ACCESS-02.** Роль по паролю (`passwordRole`): сначала пароль сравнивается с `ADMIN_PASSWORD`, потом с `ACCESS_PASSWORD`. Совпал с админским — `admin`, с клиентским — `client`, ни с одним — роли нет. Сравнение точное, с учётом регистра.
- **ACCESS-03.** `ADMIN_PASSWORD`, равный `ACCESS_PASSWORD`, админом не делает: с ним входят как клиент. Не задан `ADMIN_PASSWORD` — администратора нет.
- **ACCESS-04.** Неверный пароль: сервер ждёт 1,5 с и отвечает `ACCESS_DENIED` с текстом «Неверный пароль». Задержка замедляет перебор. Пароль не строка или пустой — тоже неверный.
- **ACCESS-05.** Не задан ни один пароль: сервер сразу, без задержки и без проверки пароля, отвечает `ACCESS_NOT_CONFIGURED` с текстом «Доступ к калькулятору ещё не настроен».
- **ACCESS-06.** Пароль проверяется в каждом POST-запросе до разбора действия. GET-запрос всегда получает `ACCESS_DENIED` с текстом «Доступ только по паролю через сайт калькулятора».
- **ACCESS-07.** Действия `catalog`, `order`, `orders`, `orderLines` доступны обеим ролям. Действия `deleteOrder`, `rebuildLayouts`, `articleLayouts`, `layoutPreviews`, `saveArticle`, `deleteArticle`, `uploadLayout`, `setOrderStatus`, `categoryRows`, `saveCategory`, `deleteCategory` — только администратору. С клиентским паролем они отвечают `ADMIN_REQUIRED` с текстом «Это действие доступно только администратору».
- **ACCESS-08.** Ответы `catalog` и `orders` содержат `role`. Ответ `orders` администратору содержит ещё `layoutsAlert` и у каждой заявки `layouts` (см. `API_CONTRACT.md`, «Список заявок»).

### Пароль в браузере

- **ACCESS-09.** Если адрес API задан, а пароля нет, сайт ничего не запрашивает и открывает [окно входа](../pages/login.md).
- **ACCESS-10.** Пароль хранится под ключом `fbprint-access-password`. Галочка «Сохранить пароль на этом устройстве» стоит — пароль кладётся в `localStorage` и стирается из `sessionStorage`. Галочки нет — наоборот: только `sessionStorage`, он переживает перезагрузку, но забывается с закрытием вкладки. Сайт, открытый в новой вкладке, такой пароль не видит и снова показывает окно входа.
- **ACCESS-11.** Пароль берётся по порядку: из памяти страницы, из `localStorage`, из `sessionStorage`. Первый найденный остаётся в памяти до выхода или ошибки доступа.
- **ACCESS-12.** Хранилище браузера недоступно (например, приватный режим): ошибки нет, пароль живёт в памяти страницы до перезагрузки.
- **ACCESS-13.** Пароль уходит в теле каждого POST-запроса, никогда в адресе ([api-and-errors.md](api-and-errors.md)).

### Роль в браузере

- **ACCESS-14.** Роль хранится только в памяти страницы. По умолчанию — клиент. `admin` ставится, только если в ответе `role` равно строке `admin`. Любое другое значение, включая отсутствие поля, — клиент.
- **ACCESS-15.** Роль обновляется после каждого ответа `catalog` и `orders`. В демо-режиме роль всегда клиентская.
- **ACCESS-16.** Ответ `ADMIN_REQUIRED` на действие администратора сразу делает роль клиентской. Это не выход: пароль не стирается, окно входа не открывается. Пользователь видит текст сервера «Это действие доступно только администратору».
- **ACCESS-17.** Вид администратора пропадает при следующей отрисовке списка заявок: метка, вкладки «Артикулы» и «Категории», папки макетов, статус и удаление заявок. Загруженные списки артикулов и категорий забываются, их открытые окна закрываются.
- **ACCESS-18.** Ошибка доступа (`ACCESS_DENIED`, `ACCESS_NOT_CONFIGURED`) в ответе на `catalog` стирает пароль, очищает каталог, делает роль клиентской и открывает окно входа ([login.md](../pages/login.md)). На других запросах реакция своя — см. [api-and-errors.md](api-and-errors.md), API-20.
- **ACCESS-19.** Админский вид в браузере — только удобство. Права проверяет сервер на каждом запросе (ACCESS-07).

### Выход

- **ACCESS-20.** Кнопка «Выйти» в [шапке](../components/data-status.md) по очереди: отменяет идущие запросы каталога и заявок; останавливает автообновление папок макетов; стирает пароль из памяти, `localStorage` и `sessionStorage`; делает роль клиентской; забывает предупреждение о Яндекс Диске, список артикулов, список заявок и время загрузки каталога; очищает каталог.
- **ACCESS-21.** После выхода хэш убирается из адреса без записи в историю. Показывается раздел «Расчёт», вид администратора скрыт, открывается окно входа с пустым полем.
- **ACCESS-22.** Черновик заявки при выходе остаётся: это данные браузера, а не таблицы. Позиции не пересчитываются, пока каталог пуст. Выбранный артикул в калькуляторе сбрасывается.
- **ACCESS-23.** Через «Выйти» меняют роль: вышли с клиентским паролем, вошли с админским, и наоборот.
- **ACCESS-24.** Выход в одной вкладке не выходит в других открытых вкладках. Там пароль остаётся в памяти страницы, и они работают до перезагрузки.

## При переносе

> [!note] При переносе
> Пароли остаются общими: клиентский и админский. Сервер хранит их хэшем `argon2id`, админский не может совпасть с клиентским. Пароль отправляется один раз в `POST /auth/login`, дальше работает сессия в cookie `HttpOnly; Secure; SameSite=Lax` на 30 дней. Пароль больше не лежит в `localStorage`. Смена пароля закрывает сессии этой роли. Чужая роль на `/admin/*` — `403`. Задержка на неверный пароль остаётся, добавляется ограничение частоты по IP ([план](../../docs/platform-plan.md), «Безопасность»).

## Вопросы

> [!warning] Расхождение
> `README.md`, «Доступ по паролю»: «хранит введённый пароль в браузере (`localStorage`)». В коде — `localStorage` только с галочкой «Сохранить пароль», без неё `sessionStorage` (ACCESS-10).

> [!warning] Расхождение
> Похоже на ошибку. «Выйти» во время запроса каталога отменяет запрос, но не забывает его. Отменённый запрос считается текущим и обрабатывается как сбой: он закрывает только что открытое окно входа и показывает «Каталог недоступен» с причиной «Сервер не ответил вовремя». Мышью так не выйдет, экран загрузки закрывает шапку. С клавиатуры выйдет: экран загрузки не мешает дойти до «Выйти» клавишей Tab ([page-loader.md](../components/page-loader.md), LOADER-14). Со списком заявок то же самое, но за окном входа этого не видно.

> [!question] Вопрос
> После `ADMIN_REQUIRED` на вкладках «Артикулы» и «Категории» роль уже клиентская, но вкладки и метка остаются до следующей отрисовки списка заявок (ACCESS-17). Скрывать ли их сразу?

> [!question] Вопрос
> Если задан только `ADMIN_PASSWORD`, клиенты войти не могут, а сервер не сообщает о неполной настройке. Так задумано?
