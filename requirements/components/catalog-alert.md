# Предупреждение об ошибке каталога

[← Оглавление](../README.md)

## Назначение

Красная плашка над шагами расчёта. Говорит, что каталог не загрузился или не обновился, и почему.

## Где используется

- [Расчёт](../pages/calculator.md) — первая строка карточки шагов, над зоной «Заявка из Excel».

## Состав

1. Заголовок жирным (`strong`).
2. Абзац с причиной и советом. Длинный текст переносится в любом месте, чтобы не вылезать за край.

## Поведение

- **CALERT-01.** Плашка скрыта, пока загрузка каталога не закончилась ошибкой.
- **CALERT-02.** Если каталог ещё ни разу не загрузился за эту сессию страницы, при ошибке показывается заголовок «Каталог не загрузился» и текст «{причина}. Без каталога расчёт недоступен.{совет}». Каталог на странице становится пустым: компаний нет, поиск выключен.
- **CALERT-03.** Если каталог уже загружался раньше, при ошибке показывается заголовок «Каталог не обновился» и текст «{причина}. Расчёт идёт по данным, загруженным в {ЧЧ:ММ}.{совет}». `{ЧЧ:ММ}` — время последней удачной загрузки. Прежний каталог остаётся, расчёт работает.
- **CALERT-04.** `{причина}` выбирается так:
  - ответ API прошёл, но каталог не прошёл проверку или в ответе ошибка — «В таблице каталога ошибка ({текст ошибки}). Сообщите об этом менеджеру FB-print». `{текст ошибки}` — сообщение из [catalog-validation.md](../rules/catalog-validation.md) или `error.message` из ответа API;
  - сервер не ответил за время тайм-аута — «Сервер не ответил вовремя»;
  - нет сети или запрос не дошёл — «Нет связи с сервером»;
  - всё остальное (HTTP-код не 2xx, ответ не JSON) — «Сервер ответил с ошибкой».
- **CALERT-05.** `{совет}` — « Обновите страницу через минуту. Если не поможет, напишите менеджеру FB-print.» (с пробелом в начале). Для ошибки в таблице каталога совета нет: текст уже говорит, что делать.
- **CALERT-06.** Плашка скрывается после следующей удачной загрузки каталога.
- **CALERT-07.** Ошибки пароля (`ACCESS_DENIED`, `ACCESS_NOT_CONFIGURED`) плашку не показывают: открывается окно входа ([login-dialog.md](login-dialog.md)).
- **CALERT-08.** В демо-режиме плашка не показывается никогда.
- **CALERT-09.** Запрос каталога, отменённый более новым запросом, плашку не трогает.
- **CALERT-10.** Кнопки закрытия у плашки нет.

Пример полного текста: «В таблице каталога ошибка (Лист «Категории», категория 7: «Стоимость» — нужно число больше нуля). Сообщите об этом менеджеру FB-print. Без каталога расчёт недоступен.»

## Состояния

| Состояние | Когда | Что видно и что доступно |
| --- | --- | --- |
| Скрыта | каталог загружен, демо-режим, ещё грузится | ничего |
| «Каталог не загрузился» | первая загрузка упала | плашка; компаний нет, поиск выключен, шаг 3 выключен |
| «Каталог не обновился» | повторная загрузка упала | плашка; расчёт по прежним данным |

## Тексты

| Где | Текст |
| --- | --- |
| Заголовок, первая загрузка | «Каталог не загрузился» |
| Текст, первая загрузка | «{причина}. Без каталога расчёт недоступен.{совет}» |
| Заголовок, повторная загрузка | «Каталог не обновился» |
| Текст, повторная загрузка | «{причина}. Расчёт идёт по данным, загруженным в {ЧЧ:ММ}.{совет}» |
| Причина: ошибка каталога | «В таблице каталога ошибка ({текст ошибки}). Сообщите об этом менеджеру FB-print» |
| Причина: тайм-аут | «Сервер не ответил вовремя» |
| Причина: нет сети | «Нет связи с сервером» |
| Причина: прочее | «Сервер ответил с ошибкой» |
| Совет | « Обновите страницу через минуту. Если не поможет, напишите менеджеру FB-print.» |

## Клавиатура и доступность

- **CALERT-11.** Плашка имеет `role="alert"`: текст зачитывается сразу, когда она появляется.

> [!warning] Расхождение
> `API_CONTRACT.md` пишет: «Ошибка при нажатии «Обновить» после успешной загрузки». Кнопки «Обновить» для каталога на сайте нет. Повторно каталог грузится после входа по паролю и после правок администратора на вкладках «Артикулы» и «Категории».

> [!warning] Расхождение
> Любая ошибка в ответе API, кроме ошибок пароля, называется «В таблице каталога ошибка (…)». Так подписывается и `CATALOG_READ_FAILED` («Не удалось прочитать таблицу: нет листа «Категории»»), и `INVALID_REQUEST`, хотя второе — не ошибка таблицы.

> [!note] При переносе
> По [плану](../../docs/platform-plan.md) каталог проверяет сервер. Ошибка в строке таблицы не попадает в базу, а сайт продолжает работать на прежних данных. Текст «В таблице каталога ошибка» клиенту, скорее всего, больше не нужен.
