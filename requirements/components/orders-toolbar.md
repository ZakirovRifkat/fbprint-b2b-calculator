# Фильтр заявок и время обновления

[← Оглавление](../README.md)

## Назначение

Переключает, какие заявки видны: все, в работе или отгруженные. Показывает, сколько заявок в каждой группе и когда список обновился.

## Где используется

- [Заявки](../pages/orders.md) — над списком заявок.

## Состав

1. Фильтр: три кнопки-переключателя со счётчиком — [ui-segmented-filter.md](../components/ui-segmented-filter.md).
2. Строка времени обновления (`#orders-sync`).

## Поведение

- **OTBAR-01.** Кнопки фильтра: «Все», «В работе», «Отгружены». После подписи — число заявок этой группы.
- **OTBAR-02.** Счётчики считаются по всему загруженному списку, а не по видимой части. «Все» — число заявок; «Отгружены» — заявки со статусом `shipped`; «В работе» — все остальные (статус пустой или любой другой).
- **OTBAR-03.** Нажата ровно одна кнопка. По умолчанию — «Все».
- **OTBAR-04.** Нажатие на кнопку выбирает группу и сразу перерисовывает список. Запроса к серверу нет.
- **OTBAR-05.** Выбор фильтра хранится только в памяти страницы. После перезагрузки страницы снова «Все». Выход его не сбрасывает.
- **OTBAR-06.** Если под фильтр не подходит ни одна заявка, вместо списка — сообщение: при «В работе» — «Все заявки отгружены.», при «Отгружены» — «Отгруженных заявок пока нет.». При «Все» такого сообщения не бывает: если заявок нет, видно пустое состояние страницы ([orders.md](../pages/orders.md), `ORDERS-19`).
- **OTBAR-07.** Счётчики и видимые заявки обновляются при каждой перерисовке списка: после загрузки, смены статуса, удаления. Если админ поставил «Отгружено» при фильтре «В работе», заявка сразу пропадает из видимых.
- **OTBAR-08.** Если заявок нет, кнопки фильтра скрыты. Строка времени видна всегда, как только список хоть раз нарисован.
- **OTBAR-09.** Строка времени показывает одно из сообщений:
  - «Обновлено в ЧЧ:ММ» — последняя загрузка удалась;
  - «Не удалось обновить заявки — показан последний загруженный список.» — ошибка, прежний список на экране;
  - «Не удалось загрузить заявки. Обновите страницу.» — ошибка, списка не было;
  - «Демо-режим: заявки появятся после подключения таблицы.» — адрес API пуст.
  Когда какое сообщение появляется — [orders.md](../pages/orders.md), `ORDERS-08`, `ORDERS-15`, `ORDERS-17`, `ORDERS-22`.
- **OTBAR-10.** Пока идёт загрузка, строка времени не меняется: видна прежняя надпись. После успеха время в «Обновлено в ЧЧ:ММ» меняется.

## Состояния

| Состояние | Когда | Что видно и что доступно |
| --- | --- | --- |
| Нет заявок | список пуст или не загружен | только строка времени |
| Есть заявки | список не пуст | три кнопки со счётчиками и строка времени |
| Фильтр пуст | в группе нет заявок | кнопки, строка времени, сообщение «Все заявки отгружены.» или «Отгруженных заявок пока нет.» |

## Тексты

| Где | Текст |
| --- | --- |
| Кнопки | «Все», «В работе», «Отгружены» + число |
| Подпись группы для экранного диктора | «Показать заявки» |
| Фильтр «В работе» пуст | «Все заявки отгружены.» |
| Фильтр «Отгружены» пуст | «Отгруженных заявок пока нет.» |
| Строка времени | см. `OTBAR-09` |

## Клавиатура и доступность

- **OTBAR-11.** Кнопки собраны в группу `role="group"` с подписью «Показать заявки». У нажатой кнопки `aria-pressed="true"`, у остальных `"false"`.
- **OTBAR-12.** Кнопки — обычные кнопки: Tab между ними, Enter и пробел выбирают. Стрелками фильтр не управляется.
- **OTBAR-13.** Строка времени — `aria-live="polite"`: экранный диктор зачитывает смену текста.

## Узкий экран

- **OTBAR-14.** На ширине до 720 px три кнопки занимают всю ширину тремя равными колонками, текст по центру и мельче. Строка времени переносится под кнопки.
- На широком экране кнопки слева, строка времени справа в той же строке.

## Зависит от

- [ui-segmented-filter.md](../components/ui-segmented-filter.md)
- [order-status-select.md](../components/order-status-select.md) — что значит «В работе» и «Отгружено»

> [!warning] Расхождение
> Фильтр называется «Отгружены», а статус — «Отгружено». Это два разных слова для одной группы.

> [!note] При переносе
> Список станет постраничным (`GET /orders?status=&cursor=`). Счётчики тогда должен считать сервер, а фильтр — передаваться в запрос `status`. Новые статусы `in_production` и `cancelled` нужно разложить по группам фильтра.
