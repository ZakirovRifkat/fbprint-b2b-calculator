# Окно отправки заявки

[← Оглавление](../README.md)

## Назначение

Модальное окно из двух шагов. Первый — подтвердить отправку и увидеть ошибку, если она случилась. Второй — номер отправленной заявки.

## Где используется

- [Расчёт](../pages/calculator.md) — открывается кнопкой «Отправить менеджеру» в [итоге панели](order-footer.md) и на [нижней полосе](order-dock.md).

## Состав

Окно ([ui-dialog.md](ui-dialog.md)) с крестиком «Закрыть» и двумя шагами.

Шаг «Подтверждение»:

1. Заголовок «Отправить заявку менеджеру?».
2. Сводка заявки.
3. Пояснение о контактах.
4. Пометка демо-режима (только в демо-режиме).
5. Скрытое поле-ловушка `website`.
6. Блок ошибки (скрыт, пока ошибки нет).
7. Кнопка «Отправить».

Шаг «Отправлено»:

1. Заголовок «Заявка отправлена».
2. Номер заявки.
3. Кнопка «Закрыть».

## Поведение

**Открытие**

- **SUBMIT-01.** Заявка пуста — окно не открывается, уведомление «Добавьте в заявку хотя бы одну позицию.»
- **SUBMIT-02.** В заявке есть позиция, которую нельзя заказать, — окно не открывается, уведомление с крестиком «В заявке есть позиции, которые нельзя заказать. Исправьте или удалите их.» ([order-draft.md](../rules/order-draft.md)).
- **SUBMIT-03.** Иначе окно открывается на шаге «Подтверждение». Прежняя ошибка скрыта, шаг «Отправлено» скрыт.
- **SUBMIT-04.** Сводка: «{N} позиция на сумму {итог}. Компания: {компании}.» Формы: «позиция / позиции / позиций». Компании — через запятую в порядке первого появления в заявке. Слово «Компания:» одно и то же при одной и нескольких компаниях.
- **SUBMIT-05.** Пометка «Демо-режим: заявка не уйдёт менеджеру.» видна, только если адрес API не задан ([api-and-errors.md](../rules/api-and-errors.md)).

**Отправка**

- **SUBMIT-06.** В демо-режиме «Отправить» закрывает окно и показывает уведомление «Демо-режим: заявка не отправлена менеджеру.» Черновик не меняется.
- **SUBMIT-07.** С адресом API «Отправить» запускает отправку ([order-submission.md](../rules/order-submission.md)).
- **SUBMIT-08.** Пока заявка уходит: кнопка недоступна и называется «Отправляем…»; крестик недоступен; Esc и клик по подложке окно не закрывают; повторное нажатие ничего не делает.
- **SUBMIT-09.** В начале отправки висящее уведомление скрывается: оно к новой попытке не относится.
- **SUBMIT-10.** Если сайт за это время обновился, страница перезагружается без отправки ([order-submission.md](../rules/order-submission.md), OSEND-07).

**Ошибка**

- **SUBMIT-11.** При ошибке окно остаётся на шаге «Подтверждение». Под пояснением появляется красный блок: «Заявка не отправлена: {причина}. Попробуйте ещё раз. Если не получится, скачайте Excel и отправьте его менеджеру.» Причины — [order-submission.md](../rules/order-submission.md), OSEND-12.
- **SUBMIT-12.** После ошибки кнопка снова «Отправить» и доступна, крестик доступен. Черновик не меняется. Повторная отправка тех же позиций несёт ту же метку попытки (OSEND-03).
- **SUBMIT-13.** Блок ошибки скрывается перед новым запросом к серверу. До этого (пока идёт проверка версии и сборка файла) старая ошибка видна.

**Успех**

- **SUBMIT-14.** После успеха окно переходит на шаг «Отправлено»: «Номер заявки: {номер}. Назовите его менеджеру, если будете уточнять детали.» Фокус — на «Закрыть».
- **SUBMIT-15.** Сразу после успеха черновик очищается (и в браузере тоже), фильтры заявки сбрасываются, список на вкладке «Заявки» и её счётчик загружаются заново ([orders.md](../pages/orders.md)). Сортировка таблицы не сбрасывается.
- **SUBMIT-16.** Если сервер принял заявку как повтор уже отправленной, окно показывает тот же номер, что и в первый раз.

**Закрытие**

- **SUBMIT-17.** Окно закрывается крестиком, кнопкой «Закрыть» на шаге «Отправлено», клавишей Esc и кликом по подложке (кроме времени отправки, SUBMIT-08).
- **SUBMIT-18.** Закрытие до отправки или после ошибки ничего не меняет: черновик и метка попытки остаются.
- **SUBMIT-19.** Если заявку отправили или очистили в другой вкладке, открытое окно закрывается само ([order-draft.md](../rules/order-draft.md), DRAFT-19).

**Ловушка для ботов**

- **SUBMIT-20.** В форме есть поле «Сайт» с именем `website`. Человек его не видит: оно унесено за левый край экрана, скрыто от диктора и не получает фокус по Tab, автозаполнение выключено. Значение поля уходит на сервер ([order-submission.md](../rules/order-submission.md), OSEND-17).

## Состояния

| Состояние | Когда | Что видно и что доступно |
| --- | --- | --- |
| Подтверждение | после открытия | сводка, пояснение, «Отправить» |
| Демо | адрес API пуст | плюс жёлтая пометка демо-режима |
| Отправка | после «Отправить» | «Отправляем…», всё закрытие заблокировано |
| Ошибка | сервер или сеть не приняли заявку | красный блок с причиной, «Отправить» снова доступна |
| Отправлено | сервер вернул номер | заголовок, номер, «Закрыть» |

## Клавиатура и доступность

- **SUBMIT-21.** Блок ошибки — `role="alert"`: диктор читает его сразу.
- **SUBMIT-22.** Окно не связано с заголовком (`aria-labelledby` нет). Начальный фокус не задан: браузер ставит его на первый доступный элемент.
- **SUBMIT-23.** На шаге «Отправлено» фокус переносится на «Закрыть».

## Вопросы

> [!note] При переносе
> По плану сервер сам пересчитывает цены. Если они не совпали с ценами клиента, он отвечает `409 PRICES_CHANGED` с новыми ценами. В окне нужен новый шаг: «цены изменились», новые цены и подтверждение. Сейчас такого шага нет: сервер только помечает расхождения в сообщении менеджеру.

> [!question] Вопрос
> Если бот заполнил поле-ловушку, сервер отвечает «ок» без номера. Окно покажет «Номер заявки: .», а черновик очистится. Для людей это не важно, но стоит ли показывать номер-заглушку?
