# Вход

[← Оглавление](../README.md)

## Назначение

Сценарий входа по общему паролю. Отдельного адреса у входа нет: это окно поверх страницы. Пароль определяет роль — клиент или администратор.

## Кто видит и как открыть

- Роли: все, до входа.
- Адрес: любой. Окно открывается само, когда пароля нет или он не подошёл.
- Как попасть: открыть сайт без сохранённого пароля или нажать «Выйти» в шапке.
- В демо-режиме входа нет ([api-and-errors.md](../rules/api-and-errors.md)).

## Состав

1. [Окно входа](../components/login-dialog.md) — поле пароля, «Сохранить пароль», кнопка «Войти», ошибка.
2. [Экран загрузки](../components/page-loader.md) — вместо окна, если пароль уже сохранён.
3. [Статус данных](../components/data-status.md) — «Нужен пароль», пока окно открыто.

## Состояния страницы

| Состояние | Когда | Что видно |
| --- | --- | --- |
| Ввод пароля | Пароля нет в браузере | Окно входа, поле пустое, пароль скрыт |
| Проверка | Нажали «Войти» | Окно открыто, на кнопке крутится индикатор, поле только для чтения |
| Ошибка | Сервер отклонил пароль | Окно открыто, под полем текст ошибки, введённый пароль выделен |
| Сохранённый пароль | Пароль есть в браузере | Экран загрузки, окно входа не показывается |
| Сохранённый пароль не подошёл | Сервер ответил `ACCESS_DENIED` | Экран загрузки сменяется окном входа с ошибкой |
| Вход выполнен | Сервер принял пароль | Окно закрыто, виден раздел по адресу |

## Требования

### Когда открывается окно

- **LOGIN-01.** Если адрес API задан, а пароля нет ни в памяти страницы, ни в браузере, при запуске открывается окно входа ([access-and-roles.md](../rules/access-and-roles.md), ACCESS-09).
- **LOGIN-02.** Если пароль сохранён, окно входа не открывается. Вместо него виден экран загрузки, пока сервер проверяет пароль и отдаёт каталог.
- **LOGIN-03.** После «Выйти» окно входа открывается сразу ([access-and-roles.md](../rules/access-and-roles.md), ACCESS-20).
- **LOGIN-04.** Окно входа открывается, если любой ответ на загрузку каталога пришёл с кодом `ACCESS_DENIED` или `ACCESS_NOT_CONFIGURED`. Так бывает, когда пароль сменили, пока страница была открыта.

### Вход

- **LOGIN-05.** Нажатие «Войти» или Enter в поле отправляет пароль. Пробелы по краям обрезаются.
- **LOGIN-06.** Пустой пароль не отправляется. Поле обязательное, браузер сам не даст отправить пустую форму. Пароль из одних пробелов молча игнорируется: ничего не происходит.
- **LOGIN-07.** Перед проверкой пароль запоминается в браузере по галочке «Сохранить пароль на этом устройстве» ([access-and-roles.md](../rules/access-and-roles.md), ACCESS-10), прошлая ошибка скрывается, кнопка переходит в состояние загрузки ([login-dialog.md](../components/login-dialog.md)).
- **LOGIN-08.** Пароль проверяется запросом каталога (`catalog`). Отдельного запроса входа нет.
- **LOGIN-09.** Пока пароль проверяется, окно входа остаётся открытым. Экран загрузки при этом не показывается.
- **LOGIN-10.** Пароль принят: окно закрывается, роль берётся из ответа, каталог показывается, статус — «Обновлено в ЧЧ:ММ», затем загружается список заявок.
- **LOGIN-11.** После входа виден раздел из адреса. После «Выйти» адрес сброшен, поэтому следующий вход открывает «Расчёт».

### Ошибки входа

- **LOGIN-12.** Неверный введённый пароль: окно остаётся открытым, под полем — «Неверный пароль». Введённый текст остаётся в поле выделенным, фокус в поле. Ответ приходит не раньше чем через 1,5 с ([access-and-roles.md](../rules/access-and-roles.md), ACCESS-04).
- **LOGIN-13.** Сохранённый пароль больше не подходит: экран загрузки скрывается, открывается окно входа с пустым полем и текстом «Сохранённый пароль больше не подходит — введите новый.».
- **LOGIN-14.** На сервере не задан ни один пароль: в окне текст «Доступ к калькулятору ещё не настроен».
- **LOGIN-15.** При любой ошибке доступа пароль стирается из браузера, каталог очищается, роль становится клиентской.
- **LOGIN-16.** Сеть, тайм-аут или ошибка сервера при проверке введённого пароля: окно входа закрывается, а ошибка показывается на странице в [предупреждении о каталоге](../components/catalog-alert.md). Пароль остаётся сохранённым, хотя сервер его не проверил.
- **LOGIN-17.** Окно входа нельзя закрыть клавишей Esc или кнопкой: без пароля калькулятор пуст.

## Данные

- `catalog` с паролем в теле — проверка пароля и загрузка каталога ([api-and-errors.md](../rules/api-and-errors.md), `API_CONTRACT.md`).
- После успеха — `orders`.

## При переносе

> [!note] При переносе
> Вход станет маршрутом `/login` и запросом `POST /auth/login`. Сервер создаёт сессию в cookie `HttpOnly`, пароль больше не хранится в браузере и не уходит с каждым запросом. Галочка «Сохранить пароль» по смыслу превращается в срок сессии. Пароли остаются общими: клиентский и админский ([план](../../docs/platform-plan.md), «Ключевые потоки» → «Вход»).

## Вопросы

> [!question] Вопрос
> При сбое сети введённый пароль остаётся сохранённым без проверки (LOGIN-16). При следующем запуске он проверится через экран загрузки. Оставить так или сохранять пароль только после ответа сервера?

> [!question] Вопрос
> Пароль из одних пробелов не вызывает никакой реакции (LOGIN-06). Показывать ли ошибку?
