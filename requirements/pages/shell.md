# Каркас: шапка, вкладки, загрузка, уведомления

[← Оглавление](../README.md)

## Назначение

Общая рамка всех разделов сайта. Шапка с вкладками, экран загрузки, окно входа и уведомления. Каркас решает, какой раздел показан, в каком порядке страница запускается и что видно до и после входа.

## Кто видит и как открыть

- Роли: все. До входа видно только окно входа или экран загрузки.
- Адрес: корень сайта, раздел — по хэшу: `#calc`, `#orders`, `#articles`, `#categories`.
- Как попасть: открыть сайт.

## Состав

Сверху вниз, в порядке на экране.

1. [Экран загрузки](../components/page-loader.md) — тёмный экран поверх всего при входе по сохранённому паролю.
2. [Метка «Администратор»](../components/admin-badge.md) — в правом верхнем углу, только у администратора.
3. [Шапка](../components/site-header.md) — логотип, [вкладки разделов](../components/view-tabs.md), [статус данных и «Выйти»](../components/data-status.md).
4. Раздел — один из четырёх, остальные скрыты:
   - [Расчёт](calculator.md) (`#calc` и любой другой хэш);
   - [Заявки](orders.md) (`#orders`);
   - [Артикулы](articles.md) (`#articles`, только администратор);
   - [Категории](categories.md) (`#categories`, только администратор).
5. [Окно входа](../components/login-dialog.md) — сценарий входа описан в [login.md](login.md).
6. [Уведомление](../components/ui-toast.md) — внизу по центру экрана.

## Состояния страницы

| Состояние | Когда | Что видно |
| --- | --- | --- |
| Первый кадр | HTML загружен, скрипты ещё не выполнились | Экран загрузки «Загружаем каталог…». Он в разметке без `hidden`, чтобы пустая страница не мелькала |
| Демо-режим | В `config.js` пустой `apiUrl` | Экран загрузки сразу скрыт. Сайт работает на демо-каталоге, входа нет. Статус «Демо-режим» |
| Нужен пароль | Адрес API задан, пароля нет или он не подошёл | Только окно входа на тёмном фоне. Содержимое страницы скрыто |
| Загрузка по сохранённому паролю | Пароль есть в браузере | Экран загрузки поверх страницы до ответа сервера |
| Работа | Каталог загружен | Шапка, вкладки, выбранный раздел. Статус «Обновлено в ЧЧ:ММ» |
| Ошибка каталога | Каталог не загрузился | Раздел виден, над калькулятором — [предупреждение](../components/catalog-alert.md), статус «Каталог недоступен» или «Не обновлено · данные от ЧЧ:ММ» |

## Требования

### Порядок запуска

- **SHELL-01.** `config.js` подключается обычным скриптом до модуля `js/main.js`. Модуль читает из него `window.FBPRINT_CONFIG`.
- **SHELL-02.** При запуске из `localStorage` удаляется старый ключ `fbprint-sent-orders`. Если хранилище недоступно, запуск идёт дальше без ошибки.
- **SHELL-03.** Начальный каталог: при пустом `apiUrl` — демо-каталог, иначе пустой каталог. Выбранная компания — первая в каталоге или пусто. Черновик заявки читается из браузера ([order-draft.md](../rules/order-draft.md)).
- **SHELL-04.** Порядок запуска: обработчики событий → начальная отрисовка каталога и заявки → отрисовка списка заявок → показ раздела по хэшу → подписка на смену хэша → подготовка вкладок «Артикулы» и «Категории» → [проверка версии](../rules/site-version.md) → загрузка каталога.
- **SHELL-05.** Загрузка каталога при запуске идёт по правилам [api-and-errors.md](../rules/api-and-errors.md) и [access-and-roles.md](../rules/access-and-roles.md). После успешной загрузки каталога сразу загружается список заявок.
- **SHELL-06.** После того как изменили артикул или категорию на вкладках администратора, каталог калькулятора загружается заново тем же способом, что и при запуске.

### Что видно до и после входа

- **SHELL-07.** Пока открыто окно входа, всё содержимое страницы, кроме окон, невидимо. Фон страницы и подложка окна — тёмные (`--ink`), прокрутка страницы отключена.
- **SHELL-08.** До входа роль — клиент: вкладок «Артикулы» и «Категории» и метки «Администратор» нет.
- **SHELL-09.** После входа клиент видит вкладки «Расчёт» и «Заявки». Администратор видит ещё «Артикулы», «Категории» и метку «Администратор» ([view-tabs.md](../components/view-tabs.md), [admin-badge.md](../components/admin-badge.md)).
- **SHELL-10.** Вид администратора включается и выключается при каждой отрисовке списка заявок. Она происходит после загрузки каталога, после загрузки заявок, после выхода и после действий над заявками.

### Разделы и адрес

- **SHELL-11.** Раздел задаёт хэш адреса. `#orders` — «Заявки». `#articles` и `#categories` — «Артикулы» и «Категории», но только у администратора. Любой другой хэш, в том числе пустой, `#calc` и `#top`, — «Расчёт».
- **SHELL-12.** Виден только один раздел. Остальные три блока `<main>` скрыты.
- **SHELL-13.** Заголовок вкладки браузера зависит от раздела: «FB-print — Расчёт стоимости», «FB-print — Заявки», «FB-print — Артикулы», «FB-print — Категории».
- **SHELL-14.** Клиент с адресом `#articles` или `#categories` видит «Расчёт». Хэш в адресе при этом не меняется.
- **SHELL-15.** При смене хэша: показывается нужный раздел, страница прокручивается в начало, фокус встаёт на заголовок `h1` раздела без дополнительной прокрутки.
- **SHELL-16.** При смене хэша на `#orders` список заявок загружается заново. На `#articles` и `#categories` загружаются артикулы или категории, если пользователь — администратор.
- **SHELL-17.** При первом открытии страницы раздел показывается по хэшу, но фокус не переносится и прокрутки нет.
- **SHELL-18.** Если администратор открыл страницу сразу с `#articles` или `#categories`, раздел появляется, когда роль стала известна: после ответа сервера на загрузку каталога.
- **SHELL-19.** Кнопки браузера «Назад» и «Вперёд» переключают разделы, потому что раздел хранится в хэше.
- **SHELL-20.** При каждой смене раздела пересчитывается [итог внизу экрана](../components/order-dock.md): он бывает только в разделе «Расчёт».

### Общие обработчики

- **SHELL-21.** Сочетание Ctrl+K (Cmd+K на Mac) в любом месте страницы ставит фокус в поле поиска артикула ([article-search.md](../components/article-search.md)). Стандартное действие браузера отменяется. Буква проверяется без учёта регистра.
- **SHELL-22.** Крупные суммы «Цена за штуку» и «Итого» подгоняются по ширине ([formatting.md](../rules/formatting.md), FMT-10) после загрузки шрифтов и при каждом изменении размера окна.
- **SHELL-23.** На странице один элемент уведомления на все разделы. Новое уведомление заменяет текущее. Поведение — в [ui-toast.md](../components/ui-toast.md).

## Данные

- При запуске — `catalog`, затем `orders` ([api-and-errors.md](../rules/api-and-errors.md), `API_CONTRACT.md`).
- При переходе на `#orders` — `orders`; на `#articles` — `articleLayouts`; на `#categories` — `categoryRows`.
- В демо-режиме запросов к API нет.

## При переносе

> [!note] При переносе
> В Angular разделы станут маршрутами: `/login`, `/`, `/orders`, `/admin/articles`, `/admin/categories` ([план](../../docs/platform-plan.md), раздел «Маршруты»). Хэш-адреса `#orders` и другие стоит перенаправлять на новые пути, чтобы старые ссылки работали. Код админских разделов загружается лениво.
