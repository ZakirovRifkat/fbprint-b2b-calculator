# Артикулы

[← Оглавление](../README.md)

## Назначение

Все артикулы обеих компаний с их макетами на Яндекс Диске. Здесь администратор находит артикулы без макета, смотрит макет крупно, добавляет, меняет и удаляет артикулы и загружает макеты. Каждая правка сразу пишется в лист артикулов компании.

## Кто видит и как открыть

- Роли: только `admin`.
- Адрес: `#articles`.
- Как попасть: вкладка «Артикулы» в шапке ([view-tabs.md](../components/view-tabs.md)). У клиента вкладки нет.

## Состав

1. Заголовок «Артикулы» и кнопка «Добавить артикул» — открывает [article-dialog.md](../components/article-dialog.md) для нового артикула.
2. Подзаголовок — текст из раздела «Тексты».
3. [articles-toolbar.md](../components/articles-toolbar.md) — фильтр по компании, «Без макета», поиск, строка «Файлов в папке макетов…».
4. Сообщение об ошибке загрузки списка.
5. Пустой результат фильтра — [ui-empty-state.md](../components/ui-empty-state.md).
6. Сетка карточек [article-card.md](../components/article-card.md).
7. Скрытое поле выбора файла для [layout-upload.md](../components/layout-upload.md).
8. Окна поверх страницы: [article-dialog.md](../components/article-dialog.md), [layout-viewer.md](../components/layout-viewer.md), [ui-confirm-dialog.md](../components/ui-confirm-dialog.md).

## Состояния страницы

| Состояние | Когда | Что видно |
| --- | --- | --- |
| Первая загрузка | вкладку открыли, список ещё не загружен | 8 серых карточек-заготовок; фильтров нет; строка статуса пустая |
| Обновление | список уже есть и загружается заново после правки | старые карточки, фильтры и строка статуса остаются |
| Готово | список загружен | фильтры, строка статуса, карточки |
| Пусто | фильтр не оставил ни одной карточки | текст пустого результата, см. [articles-toolbar.md](../components/articles-toolbar.md) |
| Ошибка, списка нет | первая загрузка не удалась | только текст ошибки над пустой сеткой; фильтров и карточек нет |
| Ошибка, список был | повторная загрузка не удалась | текст ошибки, под ним прежние фильтры и карточки |

## Требования

- **ARTS-01.** Вкладка видна только при роли `admin`. Адрес `#articles` при роли `client` показывает «Расчёт».
- **ARTS-02.** Список загружается запросом `articleLayouts`, только когда роль `admin` и открыт адрес `#articles`. При входе на другую вкладку список не грузится.
- **ARTS-03.** Список загружается один раз за сессию страницы. Повторное открытие вкладки показывает уже загруженный список без запроса.
- **ARTS-04.** Заново список грузится только: после сохранения или удаления артикула, после загрузки макета, после перезагрузки страницы. Кнопки «Обновить» нет.
- **ARTS-05.** Пока идёт запрос, второй запрос списка не отправляется: все вызовы ждут первый.
- **ARTS-06.** Индикатор загрузки виден с первого кадра вкладки: заготовки карточек рисуются до ответа сервера.
- **ARTS-07.** Пока идёт загрузка, у раздела `aria-busy="true"`.
- **ARTS-08.** Ошибка загрузки показывается текстом над карточками (`role="alert"`). Текст — по [api-and-errors.md](../rules/api-and-errors.md): у кодов `*_FAILED` и `ADMIN_REQUIRED` — сообщение сервера как есть, иначе «Артикулы не загрузились: {причина}». Пример: «Артикулы не загрузились: Сборка макетов не настроена: нет токена Яндекс Диска».
- **ARTS-09.** Если первая загрузка не удалась, повторить можно уходом с вкладки и возвратом на неё или перезагрузкой страницы.
- **ARTS-10.** После обновления списка все превью карточек запрашиваются заново: файлы на Диске могли смениться. Крупные превью окна просмотра не сбрасываются.
- **ARTS-11.** Если роль сменилась на `client` (выход, вход другим паролем), список, превью и очередь превью забываются, окна артикула и просмотра закрываются, вкладка скрывается, открывается «Расчёт».

> [!warning] Расхождение
> Ответ `ADMIN_REQUIRED` на действие с этой страницы только меняет роль в памяти. Вкладка и список остаются на экране до следующей перерисовки списка заявок (загрузка каталога или заявок). Правило — в [access-and-roles.md](../rules/access-and-roles.md).
- **ARTS-12.** Ответ `articleLayouts` содержит каждую строку обоих листов артикулов, где заполнен артикул (колонка C), в порядке листов: сначала «Глобал Фуд», потом «Студия Вкуса». Строки без артикула пропускаются.
- **ARTS-13.** Макет каждой строки выбирается тем же правилом, что и при сборке папки заявки: [layouts.md](../rules/layouts.md).
- **ARTS-14.** После сохранения или удаления артикула сайт загружает заново и список артикулов, и каталог калькулятора. Так новый, изменённый или удалённый артикул сразу виден на вкладке «Расчёт».
- **ARTS-15.** Перезагрузка каталога после правки показывает экран загрузки «Загружаем каталог…» поверх всей страницы ([page-loader.md](../components/page-loader.md)), пока каталог не придёт.
- **ARTS-16.** После загрузки макета заново грузится только список артикулов. Каталог не перезагружается.
- **ARTS-17.** При переходе на вкладку фокус ставится на заголовок «Артикулы», страница прокручивается наверх. Заголовок окна браузера — «FB-print — Артикулы».

> [!warning] Расхождение
> Счётчик «Артикулов» на вкладке «Категории» после правки артикула не обновляется: вкладка «Категории» тоже грузится один раз за сессию. Подробно — в [categories.md](categories.md).

> [!note] При переносе
> Адрес станет `/admin/articles`. Список — `GET /admin/articles`, превью — отдельная картинка по адресу `GET /admin/layouts/{id}/preview`. Правки защищает `version` и `If-Match` вместо номера строки. Артикулы синхронизируются с Google-таблицей в обе стороны ([план](../../docs/platform-plan.md)).

## Данные

| Запрос | Когда | Тайм-аут |
| --- | --- | --- |
| `articleLayouts` | первое открытие вкладки; после правки, удаления, загрузки макета | 60 с |
| `layoutPreviews` | карточка с макетом подошла к экрану; окно просмотра | 60 с |
| `saveArticle` | «Сохранить» в окне артикула | 30 с |
| `deleteArticle` | подтверждено удаление | 30 с |
| `uploadLayout` | выбран файл макета | 180 с |
| `catalog` | после `saveArticle` и `deleteArticle` | общий тайм-аут каталога |

Ответ `articleLayouts`: `companies`, `files` (сколько файлов в папке макетов), `fileNames` (имена файлов по алфавиту — для подсказки в поле «Макет»), `articles` (у каждого `companyId`, `row`, `sku`, `name`, `size`, `category`, `color`, `layoutCell`, `layout`, `path`, `url`, `problem`, `candidates`). Ошибки: `ADMIN_REQUIRED`, `LAYOUTS_NOT_CONFIGURED`, `ARTICLES_READ_FAILED` («Не удалось прочитать артикулы и макеты: {причина}»; если Диск не принял токен — причина «Яндекс Диск не принимает токен — макеты не собираются. Замените YANDEX_DISK_TOKEN в свойствах скрипта.»).

Общие правила запросов — [api-and-errors.md](../rules/api-and-errors.md), формат — `API_CONTRACT.md`, раздел «Артикулы и макеты».
