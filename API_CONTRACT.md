# API-контракт каталога FB Print

Версия схемы: `1`.

## Назначение

Google Apps Script только читает Google Sheets, отбрасывает пустые и служебные строки и возвращает каталог. Поиск, проверка тиража, выбор цены и расчёт суммы выполняются в браузере. API не изменяет таблицу и не рассчитывает стоимость заказа.

## Запрос

```http
GET <apiUrl>?action=catalog
```

Параметр `ts`, который фронтенд добавляет для обхода кеша, API может игнорировать.

## Успешный ответ

Заголовок ответа: `Content-Type: application/json; charset=utf-8`.

```json
{
  "schemaVersion": 1,
  "version": "2026-11-03T08:30:00.000Z",
  "companies": [
    {
      "id": "global_food",
      "name": "Глобал Фуд"
    },
    {
      "id": "studio_vkusa",
      "name": "Студия Вкуса"
    }
  ],
  "categories": [
    {
      "id": "27",
      "size": "80 × 120 мм",
      "color": "Текст с фоном",
      "minimumQuantity": 4200,
      "rollQuantity": 1400,
      "lanes": 3,
      "multiple": 4200,
      "prices": {
        "standard": 1.2,
        "urgent": 1.8,
        "emergency": 2.4
      },
      "reducedRun": {
        "minQuantity": 1400,
        "maxQuantity": 4199,
        "price": 1.62
      }
    }
  ],
  "articles": [
    {
      "companyId": "global_food",
      "sku": "10165",
      "categoryId": "27",
      "name": "ЭТИКЕТКА ГРУДКА КУРИНАЯ С КАРТОФЕЛЕМ..."
    }
  ]
}
```

## Правила полей

- `schemaVersion` — номер версии структуры ответа; текущая версия `1`.
- `version` — метка набора данных или ISO-дата формирования ответа.
- Все `id`, `companyId`, `categoryId` и `sku` передаются строками. Так артикулы с ведущими нулями не теряются.
- Все цены и количества передаются JSON-числами, без `₽`, пробелов и десятичной запятой.
- Цены передаются так, как они хранятся в ячейке. Например, срочная цена категории 6 — `=0,75×1,5`: таблица показывает «1,13 ₽», а API передаёт `1.125`. Хвосты двоичной арифметики вроде `1.6199999999999999` допустимы.
- Фронтенд округляет каждую цену до копеек, как таблица показывает её на экране: `1.125` → `1.13`. Сумма позиции — тираж × округлённая цена, тоже до копеек: 5 600 × 1,13 = 6 328 ₽.
- `company.id` и `category.id` уникальны.
- Сочетание `article.companyId + article.sku` уникально.
- Каждый `article.companyId` ссылается на существующую компанию.
- Каждый заполненный `article.categoryId` ссылается на существующую категорию. Артикулы с пустым `categoryId` фронтенд скрывает.
- `minimumQuantity` и `multiple` — положительные целые числа.
- Все три значения в `prices` обязательны и больше нуля.
- `rollQuantity`, `lanes` и `reducedRun` могут быть `null`, если в таблице нет данных.
- `reducedRun` задаёт диапазон сниженного тиража и его цену. Фронтенд применяет её к тиражу от `minQuantity` до `maxQuantity`, только со стандартным сроком. Тираж ниже `reducedRun.minQuantity` (или ниже `minimumQuantity`, если `reducedRun` нет) не принимается.

Все эти правила проверяет фронтенд, а не Apps Script. Ошибка называет место словами таблицы, например: «Лист «Категории», категория 7: «Стоимость» — нужно число больше нуля». Фронтенд также принимает числовые идентификаторы и цены вида `"1,20 ₽"`.

## Соответствие Google Sheets

### Лист `Категории`

| Колонка | Поле JSON |
| --- | --- |
| A | `id` |
| B | `size` |
| C | `color` |
| D | `prices.standard` |
| E | `minimumQuantity` |
| F | `rollQuantity` |
| G | `lanes` |
| H | `multiple` |
| J | `prices.emergency` |
| L | `prices.urgent` |
| O | `reducedRun.minQuantity` |
| Q | `reducedRun.maxQuantity` |
| R | `reducedRun.price` |

Строка 1 — заголовки, данные начинаются со строки 2. Apps Script включает только строки, в которых колонка A содержит идентификатор категории. Текстовые примечания под таблицей игнорируются.

### Листы артикулов

Для `Список_артикулов_ГлобалФуд` используется `companyId: "global_food"`, для `Список_артикулов_СтудияВкуса` — `companyId: "studio_vkusa"`.

| Колонка | Поле JSON |
| --- | --- |
| A | `categoryId` |
| C | `sku` |
| F | `name` |

Строка 1 — название компании, строка 2 — заголовки, данные начинаются со строки 3. Строка пропускается, если колонки A, C и F пустые.

Артикул с пустой категорией (колонка A) считается неготовым: фронтенд его не показывает и ошибкой не считает. Когда категорию заполнят, артикул появится на сайте сам. Если категория заполнена, но не заполнены артикул или наименование, фронтенд покажет ошибку.

Над заголовками нельзя вставлять строки ни на одном листе: Apps Script отсчитывает их по номеру.

Компания определяется настройкой листа, а не значением колонки B (`Площадка`). Размер, цветность, стоимость, минимум и кратность из листов артикулов не дублируются в JSON: фронтенд получает их по `categoryId` из массива `categories`.

Чтобы добавить новую компанию, допишите её в массив `COMPANIES` в `apps-script/Code.gs`: `id`, название и имя листа. Apps Script добавит запись в `companies`, прочитает лист и присвоит его строкам этот `companyId`. Фронтенд отрисует новую компанию без изменения разметки.

## Ответ с ошибкой

Apps Script не умеет менять HTTP-статус, поэтому ошибка приходит с кодом 200 в теле ответа:

```json
{
  "error": {
    "code": "CATALOG_READ_FAILED",
    "message": "Не удалось прочитать таблицу: нет листа «Категории»"
  }
}
```

| Код | Когда |
| --- | --- |
| `UNKNOWN_ACTION` | `action` отсутствует или не равен `catalog` |
| `CATALOG_READ_FAILED` | лист не найден, нет доступа или другая ошибка чтения |

`message` фронтенд показывает пользователю как есть.

## Поведение фронтенда при ошибке

- Если `apiUrl` пуст, используются демо-данные.
- Если `apiUrl` задан, демо-данные не показываются никогда.
- Ошибка при первой загрузке: каталог пуст, поиск отключён, над калькулятором — красное предупреждение с причиной.
- Ошибка при нажатии «Обновить» после успешной загрузки: остаются последние загруженные данные, предупреждение называет причину и время загрузки.
- Причины: сеть, тайм-аут, HTTP-ошибка, ответ не JSON, `error` в ответе, нарушение правил полей.

## Отправка заявки

```http
POST <apiUrl>
Content-Type: text/plain;charset=UTF-8
```

Тело — JSON-строка. Заголовок `text/plain` браузер ставит сам: так нет CORS-предзапроса, который Apps Script не поддерживает.

```json
{
  "action": "order",
  "number": "FB-0311-0042",
  "website": "",
  "catalogVersion": "2026-11-03T08:30:00.000Z",
  "total": 9578,
  "lines": [
    {
      "company": "Глобал Фуд",
      "sku": "10167",
      "name": "ЭТИКЕТКА ВЕРХ БОРЩ УКРАИНСКИЙ С КУРИЦЕЙ 1 КГ",
      "quantity": 5600,
      "urgency": "Срочный",
      "unitPrice": 1.13,
      "total": 6328,
      "condition": ""
    }
  ]
}
```

- `number` — номер заявки `FB-ДДММ-1234`, его создаёт фронтенд и показывает клиенту.
- Персональных данных нет: имя, телефон и почта не передаются. Лишние поля Apps Script игнорирует.
- `website` — поле-ловушка, у людей всегда пустое.
- `condition` пустой, если тираж оптимальный.
- Успех: `{ "ok": true }`.
- Ошибки: `UNKNOWN_ACTION`, `INVALID_ORDER`, `TOO_MANY_ORDERS`, `ORDER_SEND_FAILED` в том же формате `error`, что и у каталога.
