# API-контракт каталога FB Print

Версия схемы: `1`.

## Назначение

Google Apps Script только читает Google Sheets, отбрасывает пустые и служебные строки и возвращает каталог. Поиск, проверка тиража, выбор цены и расчёт суммы выполняются в браузере. При чтении каталога API не изменяет таблицу и не рассчитывает стоимость заказа. API пишет только строки отправленных заявок на листы «Заявки» и «Позиции заявок» (см. «Отправка заявки»), колонки F–H «Заявок» о папке макетов (см. «Папки макетов») и удаляет заявки по запросу администратора (см. «Удаление заявки»). Менеджер отмечает на «Заявках» отгрузку, а сайт читает список заявок (см. «Список заявок»). На листах артикулов есть колонка H «Макет» — каталог её не читает.

## Запрос

```http
POST <apiUrl>
Content-Type: text/plain;charset=UTF-8

{"action": "catalog", "password": "…"}
```

Пароль сравнивается со свойствами скрипта `ADMIN_PASSWORD` (сначала) и `ACCESS_PASSWORD`. GET-запрос и запрос без верного пароля получают `ACCESS_DENIED` и не видят каталог.

## Роли

- `client` — пароль `ACCESS_PASSWORD`. Всё, что было до ролей: каталог, заявки, список заявок.
- `admin` — пароль `ADMIN_PASSWORD`. То же, что у клиента, плюс папки макетов в списке заявок, `deleteOrder`, `rebuildLayouts`, `articleLayouts`, `layoutPreviews`, `saveArticle`, `deleteArticle`, `uploadLayout` и `setOrderStatus`.
- `ADMIN_PASSWORD`, равный `ACCESS_PASSWORD`, админом не делает: с ним входят как клиент. Не задан `ADMIN_PASSWORD` — администратора нет.
- Ответы `catalog` и `orders` несут `"role": "client" | "admin"`. Сайт роль не хранит, хранит только пароль; скрипт определяет роль по паролю заново на каждом запросе.
- Действие администратора с паролем клиента получает `ADMIN_REQUIRED`. Это не выход: сайт переключается в роль клиента и не спрашивает пароль снова.

Заголовок ответа: `Content-Type: application/json; charset=utf-8`.

```json

  "schemaVersion": 1,
  "version": "2026-11-03T08:30:00.000Z",
  "companies": [
    {
      "id": "global_food",
      "name": "Глобал Фуд"
    },
    {
      "id": "studio_vkusa",
      "name": "Студия Вкуса"
    }
  ],
  "categories": [
    {
      "id": "1",
      "size": "80 × 120 мм",
      "color": "Текст с фоном",
      "minimumQuantity": 4000,
      "rollQuantity": 1000,
      "lanes": 4,
      "multiple": 4000,
      "prices": {
        "standard": 1,
        "urgent": 1.5,
        "emergency": 2
      },
      "reducedRun": {
        "minQuantity": 1000,
        "maxQuantity": 3999,
        "price": 1.4
      }
    }
  ],
  "articles": [
    {
      "companyId": "global_food",
      "sku": "1001",
      "categoryId": "1",
      "name": "ЭТИКЕТКА САЛАТ…"
    }
  ]
}
```

## Правила полей

- `role` — `client` или `admin`, см. «Роли». Фронтенд читает его до проверки каталога; любое другое значение считается `client`.
- `schemaVersion` — номер версии структуры ответа; текущая версия `1`.
- `version` — метка набора данных или ISO-дата формирования ответа.
- Все `id`, `companyId`, `categoryId` и `sku` передаются строками. Так артикулы с ведущими нулями не теряются.
- Все цены и количества передаются JSON-числами, без `₽`, пробелов и десятичной запятой.
- Цены передаются так, как они хранятся в ячейке. Например, срочная цена — формула `=0,75×1,5`: таблица показывает «1,13 ₽», а API передаёт `1.125`. Хвосты двоичной арифметики вроде `1.6199999999999999` допустимы.
- Фронтенд округляет каждую цену до копеек, как таблица показывает её на экране: `1.125` → `1.13`. Сумма позиции — тираж × округлённая цена, тоже до копеек: 5 600 × 1,13 = 6 328 ₽.
- `company.id` и `category.id` уникальны.
- Сочетание `article.companyId + article.sku` уникально.
- Каждый `article.companyId` ссылается на существующую компанию.
- Каждый заполненный `article.categoryId` ссылается на существующую категорию. Артикулы с пустым `categoryId` фронтенд скрывает.
- `minimumQuantity` и `multiple` — положительные целые числа.
- Все три значения в `prices` обязательны и больше нуля.
- `rollQuantity`, `lanes` и `reducedRun` могут быть `null`, если в таблице нет данных.
- `reducedRun` задаёт диапазон сниженного тиража и его цену. Фронтенд применяет её к тиражу от `minQuantity` до `maxQuantity`, только со стандартным сроком. Тираж ниже `reducedRun.minQuantity` (или ниже `minimumQuantity`, если `reducedRun` нет) не принимается.

Все эти правила проверяет фронтенд, а не Apps Script. Ошибка называет место словами таблицы, например: «Лист «Категории», категория 7: «Стоимость» — нужно число больше нуля». Фронтенд также принимает числовые идентификаторы и цены вида `"1,20 ₽"`.

## Соответствие Google Sheets

### Лист `Категории`

| Колонка | Поле JSON |
| --- | --- |
| A | `id` |
| B | `size` |
| C | `color` |
| D | `prices.standard` |
| E | `minimumQuantity` |
| F | `rollQuantity` |
| G | `lanes` |
| H | `multiple` |
| J | `prices.emergency` |
| L | `prices.urgent` |
| O | `reducedRun.minQuantity` |
| Q | `reducedRun.maxQuantity` |
| R | `reducedRun.price` |

Строка 1 — заголовки, данные начинаются со строки 2. Apps Script включает только строки, в которых колонка A содержит идентификатор категории. Текстовые примечания под таблицей игнорируются.

### Листы артикулов

Для `Список_артикулов_ГлобалФуд` используется `companyId: "global_food"`, для `Список_артикулов_СтудияВкуса` — `companyId: "studio_vkusa"`.

| Колонка | Поле JSON |
| --- | --- |
| A | `categoryId` |
| C | `sku` |
| F | `name` |

Строка 1 — название компании, строка 2 — заголовки, данные начинаются со строки 3. Строка пропускается, если колонки A, C и F пустые.

Колонка H «Макет» — имя файла макета артикула в папке макетов на Яндекс Диске, например `ГФ_10165_3_80x120.jpg`. Каталог её не читает и на сайт не отдаёт; она нужна только сборке папок макетов (см. «Папки макетов»).

Артикул с пустой категорией (колонка A) считается неготовым: фронтенд его не показывает и ошибкой не считает. Когда категорию заполнят, артикул появится на сайте сам. Если категория заполнена, но не заполнены артикул или наименование, фронтенд покажет ошибку.

Над заголовками нельзя вставлять строки ни на одном листе: Apps Script отсчитывает их по номеру.

Компания определяется настройкой листа, а не значением колонки B (`Площадка`). Размер, цветность, стоимость, минимум и кратность из листов артикулов не дублируются в JSON: фронтенд получает их по `categoryId` из массива `categories`.

Чтобы добавить новую компанию, допишите её в массив `COMPANIES` в `apps-script/Code.gs`: `id`, название и имя листа. Apps Script добавит запись в `companies`, прочитает лист и присвоит его строкам этот `companyId`. Фронтенд отрисует новую компанию без изменения разметки.

## Ответ с ошибкой

Apps Script не умеет менять HTTP-статус, поэтому ошибка приходит с кодом 200 в теле ответа:

```json
{
  "error": {
    "code": "CATALOG_READ_FAILED",
    "message": "Не удалось прочитать таблицу: нет листа «Категории»"
  }
}
```

| Код | Когда |
| --- | --- |
| `ACCESS_DENIED` | нет пароля, неверный пароль или GET-запрос; сайт снова показывает окно входа |
| `ACCESS_NOT_CONFIGURED` | в свойствах скрипта не задан ни `ACCESS_PASSWORD`, ни `ADMIN_PASSWORD` |
| `ADMIN_REQUIRED` | действие администратора с паролем клиента: «Это действие доступно только администратору» |
| `INVALID_REQUEST` | тело запроса не JSON |
| `UNKNOWN_ACTION` | `action` не равен `catalog`, `order`, `orders`, `orderLines`, `deleteOrder`, `rebuildLayouts`, `articleLayouts`, `layoutPreviews`, `saveArticle`, `deleteArticle`, `uploadLayout` или `setOrderStatus` |
| `CATALOG_READ_FAILED` | лист не найден, нет доступа или другая ошибка чтения |
| `INVALID_ORDER_NUMBER` | `deleteOrder`, `rebuildLayouts`: номер не начинается с `FB-` и цифр |
| `ORDER_NOT_FOUND` | `deleteOrder`, `rebuildLayouts`: такой заявки нет на листе «Заявки» |
| `ORDER_DELETE_FAILED` | `deleteOrder`: таблица занята или не записалась |
| `LAYOUTS_NOT_CONFIGURED` | `rebuildLayouts`, `articleLayouts`, `layoutPreviews`: не задан `YANDEX_DISK_TOKEN` |
| `ARTICLES_READ_FAILED` | `articleLayouts`: не удалось прочитать листы артикулов или папку макетов |
| `ARTICLE_INVALID` | `saveArticle`: нет артикула или наименования, пробел или `_` `/` `\` в артикуле, нет такой категории, неизвестная компания |
| `ARTICLE_DUPLICATE` | `saveArticle`: такой артикул уже есть на листе этой компании |
| `ARTICLE_CHANGED` | `saveArticle`, `deleteArticle`: в строке уже другой артикул или её нет — таблицу изменили |
| `ARTICLE_SAVE_FAILED`, `ARTICLE_DELETE_FAILED` | не удалось записать лист или он занят |
| `LAYOUT_UPLOAD_INVALID` | `uploadLayout`: не JPG/PNG/PDF, пустой файл или больше 20 МБ |
| `LAYOUT_UPLOAD_FAILED` | `uploadLayout`: Яндекс Диск не принял файл |
| `ORDER_STATUS_FAILED` | `setOrderStatus`: не удалось записать статус |
| `LAYOUT_PREVIEW_FAILED` | `layoutPreviews`: Яндекс Диск не отдал превью (например, не принял токен) |
| `LAYOUTS_QUEUE_FAILED` | `rebuildLayouts`: не удалось записать статус на лист |

`message` фронтенд показывает пользователю как есть.

## Поведение фронтенда при ошибке

- Если `apiUrl` пуст, используются демо-данные.
- Если `apiUrl` задан, демо-данные не показываются никогда.
- Ошибка при первой загрузке: каталог пуст, поиск отключён, над калькулятором — красное предупреждение с причиной.
- Ошибка при нажатии «Обновить» после успешной загрузки: остаются последние загруженные данные, предупреждение называет причину и время загрузки.
- Причины: сеть, тайм-аут, HTTP-ошибка, ответ не JSON, `error` в ответе, нарушение правил полей.

## Отправка заявки

```http
POST <apiUrl>
Content-Type: text/plain;charset=UTF-8
```

Тело — JSON-строка. Заголовок `text/plain` браузер ставит сам: так нет CORS-предзапроса, который Apps Script не поддерживает.

```json
{
  "action": "order",
  "password": "…",
  "website": "",
  "catalogVersion": "2026-11-03T08:30:00.000Z",
  "total": 9578,
  "lines": [
    {
      "company": "Глобал Фуд",
      "sku": "1002",
      "name": "ЭТИКЕТКА СУП…",
      "quantity": 5600,
      "urgency": "Срочный",
      "unitPrice": 1.13,
      "total": 6328,
      "condition": ""
    }
  ]
}
```

- Номер заявки присылать не нужно: Apps Script берёт самый большой номер на листе «Заявки», прибавляет единицу и дату по Москве (`FB-0001 от 09.11.2026`, `FB-0002 от 09.11.2026`…) и возвращает номер в ответе. Номер из запроса игнорируется.
- `file` — необязательный Excel заявки в base64: та же таблица, что клиент скачивает кнопкой «Скачать Excel». Apps Script принимает только .xlsx до 500 КБ и пересылает его в Telegram файлом `FB-0042 от 09.11.2026.xlsx` следом за сообщением. Если файла нет или Telegram его не принял, заявка всё равно считается отправленной.
- В заявке от 1 до 300 позиций; больше — `INVALID_ORDER`.
- Если сообщение со всеми позициями длиннее 4 000 символов, в Telegram уходит сводка: компания, число позиций, позиции с расхождениями и итог; полный список — в Excel заявки.
- Персональных данных нет: имя, телефон и почта не передаются. Лишние поля Apps Script игнорирует.
- `website` — поле-ловушка, у людей всегда пустое.
- Цены и суммы в заявке Apps Script не пересчитывает, но сверяет с таблицей по правилам сайта и помечает расхождения в сообщении менеджеру. Подделанная заявка всё равно отправляется — с пометками.
- `condition` пустой, если тираж оптимальный.
- Успех: `{ "ok": true, "number": "FB-0042 от 09.11.2026" }`. Отклонённая заявка номер не расходует.
- Сначала заявка записывается на лист «Заявки» одной строкой — так номер сразу занят: колонки A–D — номер, дата и время, компания (несколько — через запятую), итого по заявке; колонку E «Статус» заполняет менеджер. Потом заявка уходит в Telegram.
- Не удалось записать на лист — `ORDER_SEND_FAILED`, в Telegram ничего не уходит. Telegram не принял заявку — её строка удаляется, ответ `ORDER_SEND_FAILED`.
- Если задан `YANDEX_DISK_TOKEN`, после отправки в Telegram заявка встаёт в очередь сборки папки макетов: в колонке G «Заявок» — «В очереди». Ответ клиенту от этого не меняется и сборки не ждёт (см. «Папки макетов»).
- Заявка тоже требует `password`; без него — `ACCESS_DENIED`.
- Ошибки: `UNKNOWN_ACTION`, `INVALID_ORDER`, `TOO_MANY_ORDERS`, `ORDER_SEND_FAILED` в том же формате `error`, что и у каталога.

## Список заявок

```json
{ "action": "orders", "password": "…" }
```

Ответ — все заявки с листа «Заявки», новые сверху, не больше 500:

```json
{
  "role": "client",
  "orders": [
    { "number": "FB-0043 от 09.11.2026", "sentAt": "2026-11-09T19:52:29.000Z", "company": "Глобал Фуд", "total": 9578, "status": "" },
    { "number": "FB-0042 от 09.11.2026", "sentAt": "2026-11-09T18:10:05.000Z", "company": "Студия Вкуса", "total": 5040, "status": "shipped" }
  ]
}
```

- Пароль один на всех, поэтому список общий: каждый клиент видит все заявки.
- Строки, где в колонке A нет номера вида `FB-…`, пропускаются.
- `status`: `shipped` — в колонке E стоит «Отгружено», пустая строка — заявка в работе.
- Позиций в ответе нет: они в сообщении Telegram и в Excel заявки.
- Без пароля — `ACCESS_DENIED`. Лист не прочитался — `ORDERS_READ_FAILED`; сайт тогда показывает последний загруженный список.
- `role` есть всегда. У клиента заявки выглядят так же, как до ролей.

Администратор получает ещё `layoutsAlert` и у каждой заявки `layouts`:

```json
{
  "role": "admin",
  "layoutsAlert": "",
  "orders": [
    { "number": "FB-0043 от 09.11.2026", "sentAt": "2026-11-09T19:52:29.000Z", "company": "Глобал Фуд",
      "total": 9578, "status": "",
      "layouts": { "status": "partial", "url": "https://disk.yandex.ru/d/AbCd", "problems": ["ГФ 10003", "ГФ 10165 — несколько файлов"] } }
  ]
}
```

- `layouts.status` — по колонке G: `''` (старая заявка или сборка выключена), `queued` («В очереди»), `building` («Собирается»), `done` («Готово»), `partial` («Не все макеты»), `empty` («Макетов нет»), `failed` («Ошибка»).
- `layouts.url` — колонка F, публичная ссылка на папку; пустая, пока папка не собрана. После «Пересобрать папку» старая ссылка остаётся и при `queued`.
- `layouts.problems` — колонка H «Проблемы с макетами», разбитая по `, `: `ГФ 10003` — файла нет; `ГФ 10165 — несколько файлов`; `СВ 15053 — нет файла «СВ_15053_x.jpg»` — файла из колонки «Макет» нет на Диске; `ГФ 10338 — файл пропал с Диска` — файл не скопировался.
- `layoutsAlert` — пусто или текст о сбое Яндекс Диска для администратора: «Яндекс Диск не принимает токен — макеты не собираются. Замените YANDEX_DISK_TOKEN в свойствах скрипта.» Пропадает сам после первого успешного ответа Диска.

## Удаление заявки

Только администратор.

```json
{ "action": "deleteOrder", "password": "…", "number": "FB-0042 от 09.11.2026" }
```

Успех: `{ "ok": true, "number": "FB-0042 от 09.11.2026", "deletedLines": 14 }`.

- Под одной блокировкой скрипт удаляет все позиции заявки с листа «Позиции заявок», затем её строку с листа «Заявки» (если строк с таким номером несколько — самую нижнюю). Позиции удаляются первыми: если номер выдадут снова, старые позиции к новой заявке не приклеятся.
- Если удалить последнюю заявку, её номер выдастся снова — как при ручном удалении строки.
- Папка макетов на Яндекс Диске остаётся: её не удаляют и не закрывают. В имени папки есть время заявки, поэтому новая заявка с тем же номером получит другую папку. В Telegram ничего не уходит.
- Ошибки: `ADMIN_REQUIRED`, `INVALID_ORDER_NUMBER` («Неверный номер заявки»), `ORDER_NOT_FOUND` («Заявка {number} не найдена — возможно, её уже удалили»), `ORDER_DELETE_FAILED` («Не удалось удалить заявку: …»).

## Папки макетов

Работают, если в свойствах скрипта задан `YANDEX_DISK_TOKEN`; иначе колонки F–H остаются пустыми.

- После отправки заявки фоновый запуск по триггеру копирует макет каждого её артикула в папку `{LAYOUTS_ORDERS_ROOT}/{номер} {время}`, например `disk:/ФБ-ПРИНТ/Макеты_по_заявкам/FB-0042 от 09.11.2026 18.10.05`. Потом публикует папку по ссылке, пишет ссылку, статус и проблемы в колонки F–H «Заявок» и шлёт ссылку в Telegram.
- Макет артикула — файл из колонки H «Макет» листа артикулов. Если она пуста — единственный файл папки макетов с именем `<буквы>_<артикул>_….jpg`. Буквы (`ГФ`, `СВ`) не сравниваются, только артикул. Артикул, который есть у обеих компаний, копируется в папку заявки один раз. Папка одна на заявку, без разделения по компаниям.
- Нет ни одного файла — папка не создаётся, статус «Макетов нет».
- Ссылка видна только администратору на сайте и в Telegram, но открыть папку может любой, у кого она есть.

## Пересобрать папку

Только администратор.

```json
{ "action": "rebuildLayouts", "password": "…", "number": "FB-0042 от 09.11.2026" }
```

Успех: `{ "ok": true, "number": "FB-0042 от 09.11.2026", "layouts": { "status": "queued", "url": "…", "problems": [] } }`.

- Заявка снова встаёт в очередь: G — «В очереди», H очищается, ссылка в F остаётся. Файлы в папке копируются заново, поверх старых.
- Ошибки: `ADMIN_REQUIRED`, `INVALID_ORDER_NUMBER`, `ORDER_NOT_FOUND`, `LAYOUTS_NOT_CONFIGURED` («Сборка макетов не настроена: нет токена Яндекс Диска»), `LAYOUTS_QUEUE_FAILED`.

## Артикулы и макеты

Только администратор. Вкладка «Артикулы» на сайте.

```json
{ "action": "articleLayouts", "password": "…" }
```

Успех:

```json
{
  "ok": true,
  "role": "admin",
  "companies": [{ "id": "global_food", "name": "Глобал Фуд" }, { "id": "studio_vkusa", "name": "Студия Вкуса" }],
  "files": 400,
  "articles": [
    {
      "companyId": "global_food", "row": 3, "sku": "10165", "name": "ЭТИКЕТКА ГРУДКА КУРИНАЯ…", "size": "80 х 120",
      "layout": "ГФ_10165_3_80x120.jpg", "path": "disk:/ФБ-ПРИНТ/ГлобалФуд_СтудияВкуса/Актуальные_макеты/ГФ_10165_3_80x120.jpg",
      "url": "https://disk.yandex.ru/client/disk/…?idApp=client&dialog=slider&idDialog=…", "problem": "", "candidates": []
    }
  ]
}
```

- Каждая строка листов артикулов с артикулом, в порядке листа. `row` — номер строки на листе.
- Макет выбирается тем же правилом, что и при сборке папки заявки. `problem`: `''` — макет есть; `missing` — файла нет; `conflict` — файлов несколько, они в `candidates`; `notFound` — в колонке «Макет» имя, которого нет на Диске.
- `url` открывает файл в веб-интерфейсе Яндекс Диска. Работает только у того, кто вошёл в аккаунт Яндекса, где лежат макеты. Файлы не публикуются.

```json
{ "action": "layoutPreviews", "password": "…", "paths": ["disk:/ФБ-ПРИНТ/…/ГФ_10165_3_80x120.jpg"] }
```

Успех: `{ "ok": true, "previews": { "disk:/…/ГФ_10165_3_80x120.jpg": "data:image/jpeg;base64,…" } }`.

- Не больше 12 путей за запрос, лишние отбрасываются.
- `size`: `M` (около 300 px, по умолчанию) или `XL` (около 800 px, для просмотра крупно). Другое значение — `M`. Ответ называет размер в поле `size`.
- Скрипт берёт у Диска превью около 300 px с токеном и отдаёт его картинкой. Готовое превью 6 часов лежит в кэше скрипта.
- Путь вне папки макетов или файл без превью — пустая строка.

## Изменение артикулов

Только администратор. Пишет прямо в лист артикулов компании.

```json
{ "action": "saveArticle", "password": "…", "company": "global_food",
  "article": { "category": "27", "sku": "19750", "size": "80 х 120", "color": "Цветная", "name": "ЭТИКЕТКА …", "layout": "" } }
```

- Без `row` — новая строка в конце листа. С `row` и `originalSku` — замена строки `row` целиком.
- Строка: A категория, B площадка (`ГФ`/`СВ` по листу), C артикул, D размер, E цветность, F наименование, H макет. Колонку G «Тираж» сайт не правит: при замене строки её значение остаётся, у новой строки она пустая. Категория и артикул из одних цифр пишутся числом.
- Если в строке `row` уже не `originalSku` — `ARTICLE_CHANGED`, ничего не пишется.
- Повтор артикула проверяется, только если артикул новый или сменился.
- Успех: `{ "ok": true, "company": "global_food", "row": 158, "sku": "19750" }`.

```json
{ "action": "deleteArticle", "password": "…", "company": "global_food", "row": 158, "sku": "19750" }
```

- Удаляет строку целиком, если в ней этот артикул; иначе `ARTICLE_CHANGED`. Строки ниже сдвигаются вверх. Макет на Диске остаётся.
- `articleLayouts` для формы отдаёт у каждого артикула ещё `category`, `color`, `layoutCell` (значение колонки H как есть) и общий список имён файлов `fileNames`.

## Загрузка макета

Только администратор.

```json
{ "action": "uploadLayout", "password": "…", "company": "global_food", "row": 145, "sku": "19747",
  "fileName": "макет.jpg", "type": "image/jpeg", "data": "<base64>" }
```

- Типы: `image/jpeg`, `image/png`, `application/pdf`; до 20 МБ. Строка `row` должна содержать `sku`, иначе `ARTICLE_CHANGED`.
- Имя файла — по правилу: `<ГФ|СВ>_<артикул>_<размер>.<расширение>`, размер из колонки D без пробелов («80 х 120» → `80x120`). Имя занято — `…_2_…`, `…_3_…`.
- Файл кладётся в `LAYOUTS_ROOT`. Имя пишется в колонку «Макет» у всех строк с этим артикулом на обоих листах.
- Прежние файлы артикула (из колонки «Макет» и подходящие по имени) уходят в корзину Яндекс Диска.
- Успех: `{ "ok": true, "name": "ГФ_19747_80x120.jpg", "path": "disk:/…", "trashed": ["ГФ_19747_1_80x120.jpg"] }`.

## Статус заявки

Только администратор.

```json
{ "action": "setOrderStatus", "password": "…", "number": "FB-0042 от 09.11.2026", "shipped": true }
```

- `shipped: true` пишет «Отгружено» в колонку E самой нижней строки с этим номером, `false` — очищает её («В работе»).
- Успех: `{ "ok": true, "number": "…", "status": "shipped" }` или `"status": ""`. Ошибки: `ADMIN_REQUIRED`, `INVALID_ORDER_NUMBER`, `ORDER_NOT_FOUND`, `ORDER_STATUS_FAILED`.
