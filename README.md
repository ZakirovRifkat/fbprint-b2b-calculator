# B2B-калькулятор FB Print

Статический фронтенд для расчёта стоимости печати этикеток и подготовки заявки из нескольких позиций.

## Запуск

Сборка и установка зависимостей не нужны. Откройте каталог проекта любым статическим HTTP-сервером, например на `http://127.0.0.1:4173/`.

Основные файлы:

- `index.html` — разметка;
- `tokens.css` — переменные дизайна: цвета, шрифты, кегли, отступы, радиусы, тени, слои, анимация;
- `style.css` — адаптивные стили, только через переменные из `tokens.css`;
- `js/` — ES-модули без сборки, вход — `js/main.js`:
  - `state.js` — общее состояние страницы;
  - `format.js` — форматы чисел и денег, склонение, мелкие помощники;
  - `catalog.js` — демо-каталог и проверка каталога из таблицы;
  - `pricing.js` — правила тиража и цены (`quote`), порог бесплатной доставки;
  - `auth.js` — пароль и окно входа;
  - `load.js` — загрузка каталога и статус в шапке;
  - `calculator.js` — шаги 1–3: компания, артикул, тираж;
  - `order.js` — заявка: строки, пересчёт цен, фильтры, страницы, итог;
  - `import.js` — заявка из Excel;
  - `orders.js` — вкладка «Заявки»;
  - `admin.js` — администратор: удаление заявок, папки макетов;
  - `submit.js` — отправка заявки;
  - `excel.js` — выгрузка в Excel;
  - `toast.js` — уведомления;
  - `confirm.js` — окно подтверждения перед удалением;
  - `main.js` — обработчики событий и запуск;
- `config.js` — адрес API и тайм-аут;
- `API_CONTRACT.md` — зафиксированная схема JSON и соответствие колонкам Google Sheets;
- `apps-script/Code.gs` — Apps Script: отдаёт каталог из таблицы, пересылает заявки в Telegram и дописывает их на лист «Заявки», собирает папки макетов на Яндекс Диске, удаляет заявки по запросу администратора;
- `apps-script/appsscript.json` — манифест Apps Script: доступ только к этой таблице, внешние запросы, триггеры и меню таблицы;
- `tests/` — тесты логики на встроенном `node:test`, без зависимостей (см. «Тесты»);
- `package.json` — только команда тестов и `"type": "module"` для Node, на сайт не влияет;
- `assets/vendor/exceljs.min.js` — ExcelJS 4.4.0 (npm, лицензия MIT в `exceljs.LICENSE.txt`). Загружается только при первом нажатии «Скачать Excel». Выбрана вместо SheetJS, потому что бесплатная версия SheetJS не записывает границы и стили ячеек.

## Тесты

Нужен Node.js 22 или новее. Устанавливать ничего не нужно:

```
npm test
```

Тесты проверяют логику без страницы: цены и тиражи (`pricing.js`), проверку каталога (`catalog.js`), разбор Excel (`import.js`), пересчёт, фильтры и страницы заявки (`order.js`), хранение пароля (`auth.js`), роль и панель администратора (`admin.js`), форматы (`format.js`). Вёрстку, окна и клики тесты не проверяют — их смотрят в браузере.

`apps-script/Code.gs` тоже проверяется в Node: `tests/gas-harness.js` загружает его в `node:vm` с поддельными таблицей, свойствами скрипта, блокировками, триггерами, Telegram и Яндекс Диском. Чистые функции (выбор файла макета, план копирования, тексты сообщений, роль по паролю) проверяет `tests/apps-script-pure.test.js`, сценарии запросов и очереди макетов — `tests/apps-script.test.js`. Настоящие Google и Яндекс Диск тесты не трогают.

## Публикация Apps Script

1. Откройте Google-таблицу с каталогом → «Расширения» → «Apps Script».
2. Замените содержимое `Code.gs` текстом из `apps-script/Code.gs`.
3. В «Настройках проекта» включите «Показывать файл манифеста appsscript.json» и замените его содержимое текстом из `apps-script/appsscript.json`. Манифест даёт четыре права: `spreadsheets.currentonly` — доступ только к этой таблице, к другим таблицам владельца скрипт не получает доступа; `script.external_request` — запросы к Telegram и Яндекс Диску; `script.scriptapp` — триггеры фоновой сборки макетов; `script.container.ui` — меню «FB Print» в таблице. Право «только чтение» (`spreadsheets.readonly`) не подходит: `SpreadsheetApp` с ним не открывает таблицу. Скрипт пишет на листы «Заявки» и «Позиции заявок»: дописывает и по запросу администратора удаляет заявки, пишет колонки F–H о макетах; функция `setupOrdersSheet` один раз настраивает колонку «Статус». На листах артикулов он пишет только колонку H «Макет» и только функциями `setupLayoutColumn` и `fillLayoutColumn`, которые запускают в редакторе (см. «Макеты на Яндекс Диске»). Остальные листы он лишь читает.
4. «Настройки проекта» → «Свойства скрипта» → добавьте `ACCESS_PASSWORD` — пароль для входа на сайт. Пока его нет, скрипт никому ничего не отдаёт. Добавьте `ADMIN_PASSWORD` — пароль администратора, другой, чем `ACCESS_PASSWORD` (см. «Администратор»).
5. Выберите функцию `test` и нажмите «Выполнить». Google попросит разрешения: таблицы Google, подключение к внешней службе, запуск триггеров и показ меню в таблице. В журнале появится число категорий и артикулов.
6. «Начать развертывание» → «Новое развертывание» → тип «Веб-приложение». «Выполнять от имени»: «Я». «У кого есть доступ»: «Все».
7. Скопируйте URL, который заканчивается на `/exec`. Если открыть его в браузере, он ответит «Доступ только по паролю» — так и должно быть.
8. Вставьте URL в `config.js`:

```js
window.FBPRINT_CONFIG = {
  apiUrl: 'https://script.google.com/macros/s/DEPLOYMENT_ID/exec',
  requestTimeoutMs: 10000
};
```

Правки в самой таблице не требуют повторной публикации: скрипт читает листы при каждом запросе. После изменения `Code.gs` откройте «Управление развертываниями», отредактируйте текущее развертывание и выберите «Новая версия» — так URL не изменится.

Если обновили и `appsscript.json` и в нём появились новые права (так было при добавлении макетов: `script.scriptapp` и `script.container.ui`), сначала выберите в редакторе любую функцию, например `test`, и нажмите «Выполнить» — Google попросит подтвердить новые права. Без этого веб-приложение и триггеры не получат доступ. Затем выпустите новую версию развертывания, как выше.

## Доступ по паролю

Доступ «Все» в настройках развертывания значит только, что запрос дойдёт до скрипта. Каталог, цены и приём заявок скрипт отдаёт лишь тем, кто прислал верный пароль из свойства `ACCESS_PASSWORD`:

- сайт при первом входе показывает окно «Вход в калькулятор» и хранит введённый пароль в браузере (`localStorage`), чтобы не спрашивать каждый раз;
- пароль уходит в теле POST-запроса, а не в ссылке, поэтому не попадает в историю браузера и журналы;
- скрипт сравнивает пароль у Google; неверный пароль отвечает с задержкой 1,5 с, чтобы перебор шёл медленно;
- открытый адрес `/exec` без пароля ничего не отдаёт;
- чтобы сменить пароль, поменяйте `ACCESS_PASSWORD` в свойствах скрипта — у всех, кто вошёл со старым, сайт снова попросит пароль. Новую версию выпускать не нужно.

Пароль один на всех клиентов. Его стоит делать длинным, от 12 символов, и менять, если он мог уйти посторонним.

## Администратор

Пароль администратора — свойство скрипта `ADMIN_PASSWORD`. Отдельного входа нет: администратор вводит свой пароль в то же окно «Вход в калькулятор». Скрипт определяет роль по паролю на каждом запросе, сайт роль не хранит.

- `ADMIN_PASSWORD` не задан — администратора нет, сайт работает как раньше.
- `ADMIN_PASSWORD` равен `ACCESS_PASSWORD` — администратора тоже нет: с этим паролем входят как клиент. `setupLayouts` предупредит об этом в журнале.
- Администратор видит всё, что клиент, и ещё на вкладке «Заявки»: ссылку на папку макетов каждой заявки, статус сборки и артикулы без макета, кнопку «Пересобрать папку» (или «Собрать папку», если папки ещё нет), а в строке заголовка каждой заявки — корзину «Удалить заявку»; предупреждение, если Яндекс Диск не принимает токен.
- Ещё у администратора есть вкладка «Артикулы». Там все артикулы обеих компаний с их макетами: превью, имя файла и ссылка на файл в Яндекс Диске. Есть поиск, фильтр по компании и фильтр «Без макета» с причиной: файла нет, файлов несколько или в колонке «Макет» имя, которого нет на Диске. Ссылка открывает файл только у того, кто вошёл в аккаунт Яндекса с макетами. Превью скрипт скачивает с токеном, файлы не публикуются.
- На общем компьютере снимите галочку «Сохранить пароль»: иначе пароль администратора останется в браузере.
- «Удалить» убирает заявку с листа «Заявки» и все её позиции с листа «Позиции заявок». Отменить нельзя. Папка макетов на Яндекс Диске остаётся. Если удалить последнюю заявку, её номер выдастся следующей заявке снова — как при ручном удалении строки. Старые позиции к новой заявке не приклеятся: они удаляются вместе с заявкой. У новой заявки будет своя папка макетов: в имени папки есть время отправки.
- Сменить пароль администратора — поменять `ADMIN_PASSWORD` в свойствах скрипта. Новую версию выпускать не нужно.

## Отправка заявки в Telegram

Кнопка «Отправить менеджеру» шлёт заявку POST-запросом в тот же Apps Script, а он пересылает её в Telegram. Токен бота хранится только в свойствах скрипта и на сайт не попадает.

Персональные данные не собираются: в заявке нет имени, телефона и почты. Менеджер получает номер заявки, компанию и позиции. Номера выдаёт Apps Script по листу «Заявки»: самый большой номер на листе плюс один, с датой по Москве — `FB-0001 от 09.11.2026`, `FB-0002 от 09.11.2026`… По дням нумерация не сбрасывается. Отдельного счётчика нет: если удалить последнюю строку листа, её номер выдастся снова; удаление строк из середины на нумерацию не влияет. Клиент видит номер в окне после отправки и на вкладке «Заявки» в шапке.

Заявка записывается на лист «Заявки» той же таблицы, а затем уходит в Telegram: одна строка — одна заявка. Колонки A–D: номер заявки, дата и время, компания (если компаний несколько — через запятую), итого по заявке. Позиции заявки — в сообщении Telegram и в Excel. Сумма — та, что прислал клиент; если цена не совпала с таблицей, это видно в сообщении Telegram. Строка 1 листа — заголовки, порядок колонок менять нельзя. Если записать не удалось (листа нет, он защищён), заявка не отправляется и клиент видит ошибку — иначе номер мог бы повториться. Если Telegram заявку не принял, её строка удаляется с листа.

Колонка E «Статус» — для менеджера: пусто или «Отгружено», другие значения таблица не примет. Строка отгруженной заявки подсвечивается зелёным. Колонку, выпадающий список и подсветку создаёт функция `setupOrdersSheet`: её запускают один раз в редакторе Apps Script («Выполнить»). Вкладка «Заявки» на сайте показывает все заявки с этого листа — новые сверху: номер, дата, компания, сумма и статус, с фильтром «Все», «В работе», «Отгружены». Пароль один на всех, поэтому список видят все клиенты. Позиции заявки на сайте не показываются — они в Telegram и в Excel. Список загружается при входе, при открытии вкладки и после отправки заявки. Пока менеджер не поставил «Отгружено», заявка считается «В работе». Свойство `ORDER_COUNTER` больше не используется, его можно удалить из свойств скрипта.

Если заявка большая и целиком в сообщение Telegram (4 000 символов) не помещается, бот присылает сводку: компания, число позиций, позиции с расхождениями цен, итог; полный список — в приложенном Excel. В одной заявке — до 300 позиций.

Следом за сообщением бот присылает Excel заявки (`FB-0042 от 09.11.2026.xlsx`) — ту же таблицу, что клиент скачивает себе. Сообщение и файл в чате — запись того, что клиент отправил; если позже он покажет другую таблицу, её можно сверить по номеру заявки.

1. В Telegram откройте @BotFather → `/newbot` и получите токен.
2. Apps Script → «Настройки проекта» → «Свойства скрипта» → добавьте `TELEGRAM_BOT_TOKEN` с токеном.
3. Менеджер пишет боту любое сообщение. Для группы — добавьте бота в группу и напишите в ней.
4. Запустите в редакторе функцию `findChatId`. В журнале появится `chat_id`. Добавьте свойство `TELEGRAM_CHAT_ID` с этим числом (у групп оно отрицательное). Для нескольких получателей укажите номера через запятую: `123456789, 987654321` — заявка придёт в каждый чат.
5. «Управление развертываниями» → редактировать → «Новая версия».

Адрес скрипта скрыть нельзя: его видно в `config.js` и во вкладке «Сеть» браузера. Поэтому скрипт защищает чат менеджера сам:

- проверяет заявку: от 1 до 50 позиций, тираж — целое число, срочность из списка;
- обрезает длинные поля, сообщение не длиннее 4000 символов;
- скрытое поле `website` — ловушка для ботов: такие заявки получают ответ «ок», но не отправляются;
- принимает не больше 20 заявок за 10 минут на всех.

Цены в заявке рассчитаны в браузере, и клиент может их подделать — через консоль браузера или отправив запрос в обход сайта. Поэтому скрипт перед отправкой сам читает таблицу и сверяет каждую позицию по тем же правилам, что сайт: артикул есть у этой компании, у него заполнена категория, тираж не меньше минимального заказа, срочность разрешена для тиража, цена за штуку совпадает с листом «Категории», сумма равна тираж × цена, «Итого» равно сумме позиций. Расхождения он не исправляет, а помечает в сообщении:

- в начале — «⚠ ВНИМАНИЕ: расхождения с таблицей в N из M поз.»;
- под позицией — что не так, например «⚠ Цена в заявке 0,50 ₽, по таблице 1,00 ₽»;
- в конце — «✅ Цены сверены с таблицей FB Print» или «⚠ Цены не совпадают с таблицей — проверьте перед счётом». Если таблица недоступна — «⚠ Цены не проверены».

Excel, приложенный к заявке, собирает браузер клиента, поэтому верить стоит пометкам в тексте сообщения. Если спама станет много, следующий шаг — капча Cloudflare Turnstile.

## Макеты на Яндекс Диске

После отправки заявки скрипт сам собирает на Яндекс Диске папку с макетами всех её артикулов, открывает к ней доступ по ссылке и присылает ссылку в Telegram следом за заявкой. Клиент этого не ждёт: папку собирает фоновый запуск по триггеру, обычно через 10–60 секунд.

Свойства скрипта:

| Свойство | Что это | По умолчанию |
| --- | --- | --- |
| `YANDEX_DISK_TOKEN` | OAuth-токен Яндекс Диска. Не задан — макеты не собираются, колонки F–H пустые | — |
| `LAYOUTS_ROOT` | папка с актуальными макетами | `disk:/ФБ-ПРИНТ/ГлобалФуд_СтудияВкуса/Актуальные_макеты` |
| `LAYOUTS_ORDERS_ROOT` | куда складываются папки заявок; не внутри `LAYOUTS_ROOT` | `disk:/ФБ-ПРИНТ/Макеты_по_заявкам` |

Свойства `LAYOUT_TRIGGER_ID`, `LAYOUT_ATTEMPTS`, `LAYOUT_FRESH`, `LAYOUT_ALERT` и `LAYOUT_ALERT_SENT_AT` скрипт ведёт сам — их не трогайте.

**Какой файл — макет артикула.** На каждом листе артикулов есть колонка H «Макет»: имя файла из папки макетов, например `ГФ_10165_3_80x120.jpg`, без пути. Если ячейка заполнена, берётся этот файл и только он. Если пуста — файл по правилу имени `<буквы>_<артикул>_….jpg`: сначала буквы, дальше артикул, дальше что угодно. Буквы `ГФ` или `СВ` не важны — раньше все макеты называли `ГФ`; сравнивается только артикул. Один артикул — один макет: у 15053, 18507 и 19455, которые есть у обеих компаний, макет общий. Папка заявки одна, без разделения по компаниям. Регистр букв и «ё»/«е» не важны. Если по правилу подходят два файла, скрипт не угадывает: артикул попадает в проблемы «несколько файлов» — впишите нужный файл в колонку «Макет».

**Колонка «Макет».** Один раз в редакторе:

1. Запустите `setupLayoutColumn` — она пишет заголовок «Макет» в H2 обоих листов артикулов. Если в H2 уже есть другой текст, лист не меняется, в журнале — ошибка.
2. Запустите `fillLayoutColumn` — она заполняет по правилу имени только пустые ячейки «Макет». Вписанное руками не трогает никогда. В журнале: сколько ячеек заполнено, артикулы без файла, артикулы с несколькими файлами (их ячейки остаются пустыми), имена в колонке, которых нет на Диске, и файлы, которые не подошли ни одному артикулу. Запускать можно сколько угодно раз — например, после загрузки новых макетов.

Колонку можно и не заполнять: пустая ячейка работает по правилу имени. Каталог сайта её не читает.

**Настройка.**

1. Получите OAuth-токен Яндекс Диска с доступом к Диску и добавьте свойство `YANDEX_DISK_TOKEN`.
2. Обновите `Code.gs` и `appsscript.json`, подтвердите новые права (см. «Публикация Apps Script»).
3. Запустите в редакторе `setupLayouts`. Она проверяет токен и обе папки, пишет в журнал число файлов и 20 примеров имён, предупреждает, если `ADMIN_PASSWORD` не задан или совпадает с `ACCESS_PASSWORD`, ставит ежечасный запуск очереди (страховка, если разовый запуск не сработал) и пишет заголовки F–H на листе «Заявки».
4. Запустите `setupLayoutColumn` и `fillLayoutColumn`.
5. Выпустите новую версию развертывания.

**Колонки «Заявок».** F «Папка макетов» — публичная ссылка на папку заявки. G «Макеты» — статус: «В очереди», «Собирается», «Готово», «Не все макеты», «Макетов нет», «Ошибка». H «Проблемы с макетами» — артикулы без скопированного макета через запятую: `ГФ 10003` — файла нет, `ГФ 10165 — несколько файлов`, `СВ 15053 — нет файла «…»` — файла из колонки «Макет» нет на Диске. У старых заявок колонки пустые.

**Папка заявки** называется номером и временем отправки по Москве: `FB-0042 от 09.11.2026 18.10.05`. Файлы в ней — с исходными именами. Если ни у одного артикула нет макета, папка не создаётся. Открыть папку может любой, у кого есть ссылка; на сайте ссылку видит только администратор.

**Меню «FB Print»** в таблице: «Собрать макеты для выделенной заявки» — выделите строку на листе «Заявки», и её папка соберётся заново сразу; «Собрать очередь макетов сейчас» — собрать всё, что ждёт, не дожидаясь триггера. На сайте то же делает кнопка администратора «Пересобрать папку».

**Сбои.** Временная ошибка Диска — до трёх попыток с паузой 5 минут, потом «Ошибка» и сообщение в Telegram. Если Диск не принимает токен (токен истёк или его отозвали), заявки ждут «В очереди», в Telegram приходит предупреждение (не чаще раза в 12 часов), администратор видит его на вкладке «Заявки». Получите новый токен и замените `YANDEX_DISK_TOKEN` — ежечасный запуск соберёт очередь сам.

**Лимиты.** На заявку уходит примерно 3 запроса к Диску плюс по одному на каждый файл, и один раз за запуск — чтение списка макетов. Бесплатный аккаунт Google даёт 20 000 внешних запросов в сутки — этого хватает с большим запасом.

При ошибке окно не закрывается и показывает причину. После успешной отправки окно показывает номер заявки. Если `apiUrl` пуст, окно работает в демо-режиме и ничего не отправляет.

Страница выполняет запрос:

```text
POST <apiUrl>  {"action": "catalog", "password": "…"}
```

Для каталога Apps Script только читает таблицу и формирует JSON, расчётов он не делает. Полный формат ответа описан в [API_CONTRACT.md](API_CONTRACT.md).

Если URL пуст, работают демо-данные. Если URL задан, демо-данные не показываются. При любой ошибке — сеть, тайм-аут, ответ не JSON, ошибка в таблице — над калькулятором появляется красное предупреждение с причиной. Если каталог ещё ни разу не загрузился, расчёт недоступен. Если ошибка случилась при «Обновить», остаются последние загруженные данные.

Листы каталога Apps Script только читает; единственное исключение — колонка H «Макет» на листах артикулов, которую заполняет `fillLayoutColumn` (только пустые ячейки). Проверяет данные фронтенд, и ошибка называет место словами таблицы: «Лист «Категории», категория 7: «Стоимость» — нужно число больше нуля». Над строками заголовков нельзя вставлять строки: скрипт отсчитывает их по номеру.

## Загрузка заявки списком

Над шагами калькулятора, выше выбора компании, — зона «Заявка из Excel»: файл `.xlsx` перетаскивают на неё или выбирают кнопкой «Выбрать файл». Другие форматы не принимаются. Клиенту не нужно переделывать свою таблицу:

- сайт ищет строку заголовков с ячейкой «Код» (или «Артикул») и столбец тиража — заголовок со словами «Тираж», «Заказ», «Количество» или «шт» (столбцы цены и суммы не берутся); необязательный столбец «Срок» распознаёт «срочный» и «экстренный»;
- название компании в строке заголовков («Глобал Фуд», «СТУДИЯ ВКУСА») задаёт компанию для строк под ним — в одном файле может быть несколько блоков; без названия берётся компания, выбранная на сайте, а если кода у неё нет, но он есть ровно у одной другой компании — она;
- без строки заголовков первый заполненный столбец — код, следующий с числом — тираж, компания — выбранная на сайте;
- строки без цифр в коде («Итого», подписи) и без тиража пропускаются; формулы читаются по их значению.

Каждая строка проверяется правилами калькулятора: «Подходит», «Сниженный тираж», «Не кратно», «Меньше минимума», «Нет в каталоге», «Повтор», «Уже в заявке». Тираж можно поправить в таблице проверки; кнопка «Исправить все по рекомендациям» доводит до кратности и до минимального заказа, переход со сниженного тиража на минимальный — только по кнопке в строке. «Добавить в заявку» переносит все строки, которые можно принять, остальные пропускаются.

## Реализовано

- динамический выбор компании из каталога;
- поиск по артикулу и наименованию, «е» и «ё» не различаются;
- подсказка, если совпадений больше шести;
- связь артикула с производственной категорией;
- три зоны тиража (пример: минимум 4 000, сниженный тираж 1 000–3 999):
  - меньше «Сниженное кол-во от» (1 000) — не принимаем, позицию нельзя добавить;
  - сниженный тираж (1 000–3 999) — цена сниженного тиража, только стандартный срок, любое количество в диапазоне без проверки кратности; показываем цену за штуку от минимального тиража и экономию на каждой штуке;
  - от минимума (4 000) — цена по срочности, кратность категории;
  - если у категории нет сниженного тиража, принимаем только от минимума;
- предложение ближайшего допустимого количества, кнопки «−» и «+» идут по допустимым значениям;
- стандартная, срочная и экстренная цена, округлённая до копеек;
- заявка из нескольких позиций; тираж позиции меняется прямо в заявке, цена пересчитывается, тираж ниже минимального не принимается;
- загрузка заявки списком (до 300 позиций) из файла `.xlsx` клиента, перетаскиванием или кнопкой, — см. «Загрузка заявки списком»;
- подсказка о доставке: бесплатная от 100 000 ₽ (порог задан в `js/pricing.js`, константа `freeDeliveryFrom`), иначе — сколько не хватает;
- выгрузка заявки в `.xlsx`: отдельный лист на каждую компанию из заявки; колонки Срочность, Артикул, Наименование, Тираж, Стоимость за шт., Итого (формула `ROUND(тираж × цена; 2)`) и скрытая колонка Размер; строка «Итого» с формулой `SUM`; рамки, жирная шапка с заливкой, закреплённая первая строка, перенос наименований, денежный формат, печать на A4 альбомом в ширину страницы;
- адаптивный интерфейс и клавиатурная навигация;
- валидация и нормализация ответа API;
- безопасный вывод текстов из каталога без вставки HTML.

Форма менеджера отправляет заявку в Telegram через Apps Script. Свой бэкенд для этого не нужен.
